# 连击计数(M17-d,E-108)

主角打中怪物时,屏幕右侧中上方出现"N HitCombo":从第 2 击起显示,数字右对齐在标签左边,颜色按计数分三档(青、黄、红);第一次出现时从屏幕右边滑进来,之后每多一击抖一下;最后一击之后过一小段时间(窗口)计数清零。本文记录客户端怎么数、怎么画、怎么动,以及我们实现了哪些、哪些没读到。

证据等级:登记函数、阈值表、颜色档与帧号规则、位置常数、缓动函数、数字的推进规则来自静态读码(高);标签与数字 2、3、5 的像素、滑入与抖动的 x 与基线逐像素吻合(高);窗口长度没读到来源,取基线标定的缺省值(低到中)。读码用 Ghidra 只读脚本导出的反汇编与我自己的反汇编脚本,基线量测是本机一次性 PIL 脚本,都是**非 REA**。

## 1. 登记:谁来数、怎么数(E-108)

- **命中回调 0x008774e0**(碰撞的 `onAttack`,每次命中、施加者一侧调一次):受击者能转成活动对象、不是无敌、不是某种特殊怪物;**施加者的所有者是本机主角**才往下走。普通模式(0x010210a0 返回 0)调 `0x008ef980(界面信息窗口, 种类 4 标志, stuck, 命中信息)`;类 PVP 的模式改调 0x008e9bb0(没读、没做)。
- **登记函数 0x008ef980**:槽数 = 种类 4 标志 + 1(普通受击者只有槽 0)。每个槽:重启"累计计时器"(时长 `this[0x5ec]`);`stuck != 0`(`.atk` 的 `[stuck]` 偶发掷骰)时不加,否则累计数加 1;累计数不小于显示阈值(表 0x015d45bc = {2, 1, 20, 10},槽 0 从 2 起显示)时,显示数 = 累计数,并重启"显示计时器"(时长 `this[0x5e8]`)。
- **窗口**:`this[0x5e8]` 与 `this[0x5ec]` 来自按(职业,成长类型)查的 16 字节记录表(全局配置单例的向量,偏移 0x7c);**表的装载处没找到**(单例指针没有任何写入点),所以窗口的毫秒数是未读项。
- **绘制之后**:显示计时器到时(`0x011ba760`:已过 ≥ 时长)→ 显示数清零。累计计时器到时的收尾块(没做):累计数不小于"技巧阈值"(表 0x015d45b4 = {5, 1})时,算技巧加成 `(累计 − 阈值) × 5 + 5`(标签第 99 帧画在 (518, 278))、播 "HK_STYLE"、记录最高连击;末尾的语音(`R_HK2_*`)也没做。
- 第二个槽(受击者种类为 4 的那一类,语义没读通,可能是空中追击的计数,对应标签第 100 帧)没做。

## 2. 画法:0x008ee7f0

- **图**:`Sprite/Common/Etc/Combo.img`(加载器 id 0x1f;与 `Combo_Big.img` id 0x5c 逐字节相同,177 帧)。每个颜色档十一帧:数字 d 的帧 = 档 × 11 + d,标签 "HitCombo" 的帧 = 档 × 11 + 10。
- **档**:显示数 ≤ 10 → 0(青,第 0–10 帧),11–20 → 1(黄,第 11–21 帧),≥ 21 → 2(红,第 22–32 帧)。
- **数字字体**:右对齐(模式 2)、间距 −6;绘制函数 0x011bce70 把 |值| 夹在 9999999,从**最后一位往前**画,每位累计 `帧宽 + 间距`,画在 `x − 累计`。取的"帧宽"是访问器 0x011b3dc0,读帧对象 +0x24;图像帧头装载函数(0x012072a0 一族)把帧头里的**画布宽高**写进 +0x24 与 +0x26(图块宽高在 +0x1c 与 +0x1e,偏移在 +0x20 与 +0x22)。所以推进量用画布宽。数字 1 的图块 19 宽、偏移 5、画布 28 宽,别的数字画布与图块一样宽。
- **位置**(普通副本):数字顶边 y = 243(0xf3),标签顶边 y + 8 = 251;x 缺省 675(0x2a3);**先画标签再画数字**,数字右对齐在标签左边缘。类 PVP 模式 y = 0x1a4、关卡类型 7 的 y = 0x131,没做。
- 标签与数字都不带染色与淡出。

## 3. 滑入与抖动:缓动函数 0x011b9a50

缓动 `Ease(从, 到, 已过, 总长, 模式)`:总长 ≤ 已过 → 到;已过 < 1 → 从;模式 1 是先快后慢(位移比例 1 − (1 − t)²),模式 0 是先慢后快(t²),t = 已过 / 总长;位移用单精度算出差值的 2 倍除以总长,再用 x87 扩展精度做二次式,最后向零取整(常数 0.5 在 0x01562184、2.0 在 0x01562188)。

标签左边缘 x(年龄 = 显示计时器已过毫秒):

| 显示数 | 年龄 | x |
|---|---|---|
| 2(第一次出现) | < 250 | 670 + Ease(110 → 0,年龄,250,先快后慢) |
| | 250 到 300 | 670 + Ease(0 → 5,年龄 − 250,50,先慢后快) |
| | ≥ 300 | 675 |
| > 2(每多一击) | < 50 | 670 + Ease(5 → 0,年龄,250,先快后慢) |
| | 50 到 100 | 670 + Ease(0 → 5,年龄 − 50,50,先慢后快) |
| | ≥ 100 | 675 |

显示计时器在每次显示数更新(计数不小于 2 的那一击)时重启。

## 4. 与基线对照(非 REA,本机已有的基线帧,只量不入库,没有新录)

- 基线 S07(攻击)、S09(击杀)、S10(首领战)里出现的连击图都是青色一档:标签(第 10 帧)与数字 2、3、5(第 2、3、5 帧)在 y = 243 与 251 处逐像素 0 失配;标签 x 序列 685、670、675 … 与 680、671、675 … 672、670、675 … 都落在上面的缓动公式上(滑入、第三击与第五击的抖动)。
- **窗口**:按截图时间戳估计,最后一击之后连击图还能看到的最长时间 1152 到 1211 毫秒、已经消失的最短时间 1214 到 1273 毫秒,所以缺省窗口取 **1200 毫秒**。
- 没有黄色、红色一档,也没有数字 1 的基线帧:这两处是读码的结论,没被基线对过。

## 5. 实现

- `ComboCounter`(`com.dnfunity.play`):累计数、显示数(≥ 2)、窗口(缺省 1200 毫秒,走界面时钟,不受命中停顿影响)、显示计时器的年龄、颜色档;静态 `LabelXAt`(§3 的表)与 `Ease`(客户端的二次缓动)。
- `ComboArt`:`For(图源)` 缺 `combo.img` 第 0 帧返回 null;`Build` 先放标签、再从最后一位往前放数字(推进量 = 画布宽 − 6,图块画在 `x − 累计 + 帧偏移`),标签与数字用叠加层大类、标签 "combo";显示数不到 2 或缺帧时什么也不放。
- `RoomCombatSession`:命中处 `_combo.Hit(界面时钟)`,每小步 `_combo.Update(界面时钟)`;`Combo` 属性是累计数;画面没有 `combo.img`(合成图包)时退回占位文字 "N HIT";原来的占位窗口 2600 毫秒改成 1200。
- 命令行:`combat-check` 的命中行打印 `连击 N(显示,第 K 档,标签 x …)` 或 `(不显示)`,连击清零时打印一行;`--shots-at … --png …` 能直接看到画面。

测试:`ComboCounterTests` 20 条(计数与窗口边界、颜色档、缓动的两种模式与边界、滑入与抖动的时间线、标签先画数字后画、右对齐与 6 像素重叠、数字 1 的画布宽推进、缺帧不画一半)、`RoomCombatTests` 2 条(位图连击与窗口走满、占位文字);全套 1362 条通过,0 警告。数据全是合成的。

## 6. 没读到、推断与没做

- **窗口表**:按职业与成长类型查的窗口毫秒数没找到装载处(缺省值是基线标定);不同职业的窗口可能不同。
- **第二个计数槽 / 种类 4 / stuck 掷骰**:没做(我们没有 stuck 掷骰,所以不会出现"命中不加数")。
- **技巧加成、"HK_STYLE" 与 `R_HK2_*` 语音、空中追击标签**:没做。
- **类 PVP 与特殊关卡类型的位置**:没做。
- **数字 1 的推进**(画布宽,读码结论)、**黄、红两档**:没被基线逐像素对过。
- 评分与"连击杀伤率"等和连击数挂钩的规则没读,不在本次范围。
