# DNF 数据格式规格

对象:用户自备的游戏目录,里面有 `Script.pvf`、`ImagePacks2/*.npk`、`DNF.exe`。
本文只记录"怎么读"的事实、统计数字与来源,不包含从原版数据里解出的素材或脚本内容。
参考实现在 `tools/py/`(Python,标准库),每条事实标注证据编号,编号对应 [证据台账](evidence/ledger.md)。

状态标记:**已验证** = 在全部文件上跑通且结果吻合;**推断** = 根据形状与取值猜的,没有引擎里的原表;**未知** = 还没研究。

## PVF(Script.pvf)  已验证  E-001

- 头:`u32 guidLen(36)`、GUID、`u32 version(66282)`、`u32 dirTreeLen(27,112,312)`、`u32 dirTreeCrc`、`u32 nFiles(334,998)`。头长 = guidLen + 20 = 56。
- 解密(目录树与每个文件相同):按 32 位小端字,`out = ROR32(word ^ crc ^ 0x81A79011, 6)`。目录树用头里的 `dirTreeCrc`,文件用自己目录项里的 `crc`。
- 目录项:`u32 fileNo, u32 pathLen, path(latin1), u32 length, u32 crc, u32 relOffset`。
- 文件数据起点 = `headerLen + dirTreeLen + relOffset`,读取长度向上对齐到 4 字节,解密后截到 `length`。
- 目录树解析完后剩 1 个字节,**未解释**。
- 目录项里的 `crc` **不是内容校验和**:抽查的 12 个 2 字节空脚本(正文都是 `B0 D0`),`crc` 各不相同;与路径的标准 CRC32 异或,在同一路径长度的组内也不是常数。它至少承担解密密钥的作用。完整性对拍用文件清单(见 `tools/py/manifest.py`),不用这个字段。
- 全库清单聚合哈希:`cb377e11645e024d9a3d775fdd613880bd520409382dbe961163878b65511154`(对清单里每个文件的十六进制 SHA-256,按目录顺序依次喂给 SHA-256)。
- 加速写法:把整段当一个大整数,逐字 XOR 与循环右移 6 位都用整数运算加掩码完成;335k 个文件解密加哈希约 2.7 秒(Python)。

文件类型:147,273 个标记流脚本(`B0 D0` 开头)、187,438 个 `.ani`(187,365 个二进制 + 73 个空文件或文本)、212 个 `.nut`(明文 Squirrel),其余是文本。

### stringtable.bin

`u32 count(395,044)`,随后 `count+1` 个 `u32` 偏移(相对第 4 字节),再往后是字符串池,字符串无终止符。第 i 个字符串 = `data[4 + off[i] : 4 + off[i+1]]`。池里既有 `[name]` 这样的标签,也有文本键、路径和 `[fixed]` 这样的关键字。

### 标记流脚本(`B0 D0`)  已验证  E-003

文件 = `B0 D0` + N 个 5 字节标记,标记 = `u8 类型 + i32 值`。147,273 个文件的正文长度全部能被 5 整除。

| 类型 | 含义 | 出现次数 |
|---|---|---|
| 2 | 整数 | 8,629,508 |
| 3 | 整数(只在 Unicode 范围表里见到) | 8 |
| 4 | 浮点(i32 位模式当 f32) | 127,854 |
| 5 | 标签,值是字符串池下标,字符串形如 `[name]` 或 `[/name]` | 3,815,867 |
| 6 | 括号词,如 `(UP)`、`(SKILL)` | 2,493 |
| 7 | 字符串或关键字,如路径、`[fixed]` | 2,726,904 |
| 8 | 分隔符 `,` | 1,721 |
| 9 + 10 | 总是成对:9 的字符串是 25 种固定值之一,10 的字符串是键(字符串引用) | 各 291,519 |

tag 目录:全库 3,408 种开标签、3,232,710 次出现。前 10 个 25.73%,前 25 个 44.85%,前 50 个 61.91%,前 100 个 76.23%,前 200 个 87.63%,前 500 个 97.17%,前 1000 个 99.45%。
**标签语义未标注。** 工具 `tools/py/tag_catalog.py` 记录了每个标签后面紧跟的值类型形状。

战斗切片相关的 14 类扩展名(act、stk、ai、obj、atk、key、ptl、til、map、mob、skl、aic、dgn、apd)联合 1,596 种标签,前 100 个覆盖 70.95%,前 200 个 86.08%,前 300 个 93.20%。

## 二进制 .ani  已验证(语法)/ 推断(属性名)  E-004

187,365 个二进制 `.ani` 全部被下面的结构恰好读到文件末尾。

```
u16 frameCount, u16 imageCount
imageCount * (u32 len, bytes path)           # NPK 里的名字 = "sprite/" + path.lower()
u16 globalCount, globalCount * (u16 id + 负载)
frameCount * 帧:
    u16 boxCount, boxCount * (u16 boxType + 6 * i32)     # 14 = 伤害框(推断), 15 = 攻击框(推断)
    u16 imageIdx                                          # 0xFFFF = 无图
    若 imageIdx != 0xFFFF: u16 frameIdx
    i32 x, i32 y, u16 propCount, propCount * (u16 id + 负载)
```

- 全局属性(id: 负载字节数):0:1, 1:1, 3:2, 18:15, 28:2。
- 帧属性:1:1, 2:8, 7:8, 8:4, 9:4, 10:1, 12:4, 13:2, 16:字符串(u32 长度 + 内容), 17:0, 23:4, 24:2, 25:0, 26:4, 27:8;11 = 图形特效:`u16` 类型(0 到 6),类型 5 之后多 3 字节。
- 已核对取值:12 是延时毫秒;16 是音效键。7(两个 f32)、8(一个 f32)、9(RGBA)、13(伤害类型)、特效类型含义均为**推断**。
- 路径里可能带 `%02d%02d` 这类占位符,运行时由装备编号替换,替换规则**未研究**。
- 端到端核对:两个 `.ani` 指到对应 IMG 帧后拼出连贯动画(4 帧枪口火焰各 60 毫秒;1 帧蜥蜴人受击)。

## NPK 与 IMG v2  已验证  E-002

- NPK:`NeoplePack_Bill\0`(16 字节)+ `u32 count` + `count * 264` 字节目录项:`u32 offset, u32 size, 256 字节名称`。名称与固定密钥逐字节异或,密钥 = `("puchikon@neople dungeon and fighter " + "DNF" * 100)[:255] + "\0"`。
- 全部 1,575 个 NPK、80,464 个条目 = 80,328 个 IMG v2 + 136 个旧版 `Neople Image File`(旧版**未解析**)。
- 49 个 IMG 名称在两个 NPK 里重复(39 个内容相同,10 个不同);引擎的覆盖顺序**未知**。
- IMG v2:32 字节头 = 16 字节魔数 + `i64 indexSize` + `i32 version(2)` + `i32 frameCount`。索引项:链接帧 8 字节(`i32 0x11, i32 target`),其他帧 36 字节(`i32 type, compress, w, h, size, x, y, frameW, frameH`)。帧数据从 `32 + indexSize` 开始,按索引顺序紧挨着。
- 像素格式:`0x0E` ARGB1555、`0x0F` ARGB4444、`0x10` ARGB8888;`0x11` 链接帧。压缩:5 未压缩、6 zlib。
- **帧数据长度的坑**:`compress=6` 时 `size` 是压缩后长度;`compress=5` 时实际长度是 `w*h*bpp`,而 16 位格式的 `size` 字段按 32 位记,直接用它推进偏移会让 901 个 IMG 整体错位。
- 例外:97 个 1×1 占位帧(类型 `0x0E`、`compress=6`、`size=4`)的 zlib 流被截断,按透明像素处理。
- 全量扫描:80,328 个 IMG 布局全部吻合;非链接帧 9,860,808 个,其中 9,860,711 个解压后长度恰好等于 `w*h*bpp`;链接帧 1,893,540 个全部在 16 跳内落到真实帧。
- 体量:解压后 40.98 GB,压缩态 3.54 GB,所以必须按需解码。
- 颜色转换(参考实现):4444 每通道 ×17;1555 用位复制 `(v<<3)|(v>>2)`。尚未与原版客户端的屏幕输出逐像素比较,所以"逐像素一致"目前是以参考实现为准,不是以原版为准。
- 混合方式(叠加等)来自 `.ani` 的图形特效属性,不在 IMG 里。

## DNF.exe(静态,磁盘字节)  E-005、E-006

见证据台账。要点:PE32 x86,41,978,368 字节,时间戳 2021-03-19 16:02:58 UTC;9 个同名 `nsn` 节(`XRW`,其中 #7 为 `XR`)、`.idata`、`.rsrc`;入口点在第 0 个 `nsn` 节(熵 6.66,0% 高熵块,形态接近未加密的 x86 代码)。
**这些不是对运行行为的观察。** 保护层(`TerSafe`、`nsn` 节、`.rsrc` 里的 `FILE` 与 `HSH` 资源)的作用**未知**,碰它之前必须先问用户。

## 未决问题

- `.ani` 属性的真名与语义;图形特效 0 到 6 各是什么混合模式(类型 2 占 98.6%,极可能是叠加类,推断)。
- 标记流脚本里每个标签的语义。
- 旧版 IMG(136 个)的格式。
- NPK 之间同名 IMG 的覆盖顺序。
- PVF 目录树的 1 个多余字节。
- 网络协议、`DNF.exe` 内部逻辑(P6、P7)。
