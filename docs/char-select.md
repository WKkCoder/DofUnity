# 选角界面与登录占位(M9e,证据 E-096)

目标:让流程从原版的起点开始——选角界面(基线 S02):一排排底座上站着账号里的角色,选中的亮着发光框,底下"游戏开始"按钮,两侧是创立、删除、选择频道、结束游戏的小按钮;
确认之后登录进城(M9d 的城镇,先经过登录加载画面)。所有图都读用户自备的图包,仓库里没有任何原版素材;位置由基线帧逐像素试摆量出来,整屏合成与基线对过。
登录本身(账号、网络)是占位:名册在进程内,只有一个本地的 1 级鬼剑士;协议部分归 P7(开工前先和用户确认范围)。

## 1 素材与数据链(观察)

- 界面图:`sprite/interface2/selectcharacter/selectcharacter.img`(整屏背景、标题、左上辉光、选中框、"游戏开始"按钮的常态/悬停/按下/灰四帧、底座亮与暗各一帧);
  `sprite/interface/windowcommon.img`(窗口边框九宫格、滚动条的箭头/滑块/轨道、小按钮的左帽/中间/右帽);`sprite/interface2/mercenary/flag.img`(右上角的旗)。
  图里**没有字**:标题与"游戏开始"是图,角色名、等级、职业、四个小按钮的文字是系统字体渲染的。
- 背景光束:三个界面动画 `ui/selectcharacter/animation/selectcharactereffect_back1.ani`、`…_back2.ani`、`selectcharactereffect.ani`(两个宽的光柱左右飘,一个粒子),共用一个原点;
  它们的图在 `…/effect/selectcharactereffectanimation.img` 里。
- 头像:鬼剑士的默认外观(`DemoHero.CreateOutfit`,与城镇里的主角同一套换装)加角色脚本的 `[rest motion]` 站立动画,摆法与城镇、副本里的主角同一个模型(`AvatarOutfit.SpritesAt`,脚下为原点)。
- 没有读界面脚本(`.ui`)的控件坐标:位置都是拿基线帧用 `dnf locate` 与逐像素滑动对比量的(同 E-088、E-091、E-094 的做法),代码里的常量写的是"量出来的"。

## 2 画面(观察:位置与帧号是对着基线 S02 量出来的)

绘制次序(都在叠加层大类,列表顺序 = 画的先后):背景 → 三个光束动画 → 窗口边框 → 标题 → 旗 → 辉光(加法)→ 滚动条(上箭头、下箭头、轨道、滑块)→
每个槽位的底座(选中的是亮的,其余与空槽是暗的,都是加法混合;选中的再叠发光框,加法)→ 每个角色的头像与两行字 → "游戏开始"按钮 → 四个小按钮(底图 + 字)。

| 部件 | 说明 |
|---|---|
| 槽位网格 | 6 列 × 2 行共 12 格,框 119×207,格距 122×210,第 0 格在左上;角色按槽位顺序连续排,先填满一行再换行 |
| 底座 | 每格一个(亮/暗两种),相对框的位置固定;选中格的亮底座与发光框是加法混合 |
| 头像脚下点 | 相对框左上角的固定点(见代码常量);头像整体用叠加层大类,按先后编号 |
| 窗口边框 | 62 × 33 块中心块(12×13)加四角与四边,拼成一张 766×451 的大图缓存(同一份图包共用,第一次画时合成) |
| 滚动条 | 上下箭头 + 1 像素高的半透明黑轨道铺满 + 滑块(上 11 行与下 12 行原样,中间重复第 11 行拉到 351 高);占位名册不会滚动,滑块高度照基线 |
| 小按钮 | 左帽 + 2 像素宽的中间块横向铺 + 右帽,合成 77×23;四个并排(创立、删除在左,选择频道、结束游戏在右),字用像素字写英文占位 |
| 两行字 | 等级加名字、职业名,水平居中于槽位,颜色是拿基线上字的像素量的 |

与基线 S02 对照(CPU 合成 vs 基线截图;基线上有真实角色的两列、右上角的冒险团标签、光束区域、四个小按钮里的中文字这几块不比):
- 第二张基线里选中的是第 1 格,用 `charselect-shot --chars 2 --select 2 --no-avatars` 画同样的选中状态来比:
  右边三列空槽(62700 像素)、第二行六个空槽(161700 像素)、"游戏开始"按钮(5375 像素)、按钮行除字框外(26516 像素)**都是 0 个像素不同**;
  选中框上半圈 5.8% 的像素有差别、没有一个差别大于 24(基线上的角色周围有粉色火焰光环,盖在框与相邻槽位上,左右两条边与火焰重叠,差别大);
  滚动条 13.5% 的像素有差别、只有 3 个像素差别大于 24(滑块上沿渐变的几行,画法只是近似);
  窗口外沿一圈 2.0% 的像素有差别,其中 98% 在顶边 x 280..480 一带(光束的阴影,算光束的差别)。
- 整幅 CPU 画面(选中第 0 格、带头像、光束停在 0 毫秒)与第二张基线比,排除上面几块之后 0.73% 的像素不同、差别大于 24 的占 0.13%、平均每通道差 0.22/255;
  与第一张基线(鼠标悬停提示与指针盖在角色上)比是 3.82% 不同、差别大于 24 的占 0.08%。
- 背景、窗口边框、标题、旗、辉光、选中框、底座、滚动条箭头、小按钮底图与"游戏开始"按钮在静态区域里逐像素一致或几乎一致,没有发现版面错位;头像与光束见 §3、§4。

## 3 头像(观察 + 推断)

- 脚下点用滑动对比量:把头像层(带头像的 CPU 画面里头像的精灵)在基线第 0 格的角色上滑动 ±10 像素,找"几乎一模一样"的像素数最多的偏移,
  峰值唯一:水平 0 像素、垂直比第一次估计低 1 像素(偏一像素就掉到三分之一以下)。小腿与脚 **100% 逐像素一致**(同一个动画帧),头与上身 73%(其余被基线上的鼠标指针和悬停提示遮住);腰腹被遮得多,对不了。
- 动画:站立动画循环(两帧),头像按界面时间(`CharacterSelectScreen.AgeMs`)取帧;基线上的角色与第一帧的相位一致,界面打开后过了多久抓的图不知道,
  所以只能说"相位对得上一个取值",不能验证时间轴本身。
- 默认外观(城镇里主角同一套)在基线第 0 格角色的小腿与脚上逐像素一致,这是"换装模型、站立动画的挑选与脚下点都对"的证据;其它部位被遮住,没对。
- 其它职业的头像、觉醒后的外观、选中角色脚下的职业光环特效(基线第 1 格有)没做;名册里的每个角色都用同一套默认外观。

## 4 光束动画(推断)

- `UiAnimation` 把一个 `.ani` 放在屏幕原点上播放:精灵位置 = 原点 + 帧偏移 + 图自带偏移;帧带图形特效 2 时用加法混合;染色 alpha 与帧间插值同城镇里的 `AnimatedEffect`(`AniTimeline`)。
- 帧偏移在两帧之间的插值没有被核对过:基线只有两张截图,光束正好都停在关键帧附近,中间值是推断(与染色 alpha 的插值同一个开关)。
- 光束区域的位置与形状大致对得上,但内部的亮度、粒子的位置对不上基线(相位不同);这一块在对照里被排除,**没有逐像素验证**。

## 5 交互(推断:原版键盘怎么操作选角没有读到客户端代码)

- 方向键在有角色的格子之间移动选中项:左右按列、上下按行,到头不循环;目标格子没有角色时,左右停在名册最后一个角色,上下不动。
- 回车、空格、点"游戏开始":用选中的角色开始游戏;Esc、点"结束游戏":结束游戏(界面的结果 `Quit`,流程不动,由宿主退出);点有角色的格子选中它;
  创立、删除、选择频道三个按钮点中了没有反应(单机没有对应功能);点没有角色的格子、界面外没有反应。有结果之后界面不再响应。
- 没做:鼠标悬停时"游戏开始"换悬停帧、按下时换按下帧(图包里有这两帧,界面没有指针跟踪);悬停提示文字;双击角色直接进游戏。

## 6 登录占位(占位)

- `CharacterRoster.Local()`:名册在进程内,只有一个 1 级的鬼剑士(名字、职业名是合成的占位,与任何真实账号无关),不读写文件、不联网。
  界面只认名册(`CharacterRoster`),以后接上本地存档或服务器的角色列表,换掉来源即可。
- 登录 = 确认选中的角色之后,流程切到城镇世界的第一站(原因记为 `login`),中间照样经过登录加载画面(M9d)。
- 没做:账号输入、频道选择、创建角色与删除角色(创角要读职业表与初始外观,和 P7 的协议一起做)。

## 7 流程

- `GameStage.CharacterSelect`:`GameFlow.EnterCharacterSelect()` 造一个新的 `CharacterSelectScreen`(选中第一个角色)并进入这个阶段;`Poll` 看到结果是 `Start` 就登录进城(`GoTown(Start, null, "login")`),
  结果是 `Quit` 不动流程。离开这个阶段之后 `GameFlow.CharacterSelect` 清成 null。构造时没给选角界面工厂的流程没有这个阶段(`EnterCharacterSelect` 报错)。
- `FlowBot`:在选角界面上推着界面的时钟走,停 1.5 秒(占位)后确认选中的角色。
- 命令行 `dnf flow-check --from char`(从选角开始,其余同 `docs/flow.md`)、`dnf charselect-shot --png <文件> [--time 毫秒] [--chars N] [--select N] [--no-avatars]`(单帧);
  播放器 `-dnfflow -dnfflowfrom char`(`-dnfshot`/`-dnftime` 离屏渲染一帧,与命令行逐字节对照)。

## 8 代码

- `Dnf.Play.CharacterSlot`/`CharacterRoster`:名册(最多 12 个,6 列 × 2 行;`Local()` 是登录占位)。
- `Dnf.Play.ICharacterAvatars`/`DnfCharacterAvatars`:头像来源接口与用户自备数据的实现(读不到素材时返回空列表并记下原因,界面照样画);实现可以注入角色脚本与换装,所以合成数据可以测。
- `Dnf.Play.UiAnimation`:界面上播放的 `.ani`(光束)。
- `Dnf.Play.CharacterSelectScene`(图包 + 头像来源 + 光束动画)、`CharacterSelectArt`(画法:位置常量、点击测试、按图包缓存的合成大图)、`CharacterSelectScreen`(逻辑与画面,`ISceneSource`);没有图包时画占位画面(深色底、像素字名单)。
- `GameFlow`(选角阶段)、`FlowBot`(停留后确认)、播放器 `TownDemo`(按键、点击、`-dnfflowfrom char`)、命令行 `FlowCheck`/`CharSelectShot`。

- 合成数据单元测试 47 条(`CharacterSelectTests`):名册与槽位(上限、空值、网格填法)、界面逻辑(移动不循环、确认与返回只认第一次、时钟只往前走、点击命中)、
  占位画面、原版画法的层次次序与每个精灵的位置(原点 + 帧偏移)、哪些层是加法混合、缺帧时的退路、合成大图的尺寸与逐像素内容(边框、滚动条、小按钮)、头像来源(位置、平移、循环与失败)、
  界面动画(摆放、循环、插值、染色)、流程里的选角阶段(起点、登录经加载画面进城、没有加载画面直接进城、Quit 不动、工厂缺失、每次新界面、回城落脚点)、自动机停留后确认。
  全套测试 1117 条通过(Squirrel 22、Script 7、Data 92、Game 369、Render 266、Play 361)。
- 与基线 S02 对照见 §2、§3;`out/` 下的对照图只在本机,不入库。
- Unity EditMode 44 条(34 通过、10 条要显卡的跳过、0 失败)。
- macOS 播放器(`tools/unity-build-town.sh macos`):离屏渲染选角界面 0、0.7、1.4 秒三个时刻与命令行 `charselect-shot` 逐字节一致(全部 45 帧对拍零差异、每通道最大差 0);
  无人值守实时从选角界面开始走完整条流程(时间步 ×4,墙钟 32.9 秒),日志里十六行 `DNF_FLOW`(第一行进入选角界面、第二行登录进加载画面)、
  末尾 `flow=Town serial=16 runs=3 settlements=3 botDone=True choicesMade=3`、声音计数没有读失败。
- 命令行 `flow-check --from char`(真实数据):十六次阶段切换、三局都打到首领清空、停在城镇;`--explore` 同样十六次;`--legacy-town` 八次。

## 10 推断、占位与没做

- **中文文字**:名字、等级、职业、四个小按钮的文字是英文像素字占位;原版是系统字体。统一的文字系统(中文字体)留到后面的"文本系统"里再做。
- **头像**:只有默认外观的鬼剑士;其它职业、觉醒外观、选中角色的光环特效没做;悬停时的角色动作变化没做。
- **光束**:帧偏移插值是推断,内部亮度与粒子位置对不上基线的相位,没有逐像素验证。
- **右上角的冒险团标签与条、悬停提示、频道提示**:没做(基线上有,含文字)。
- **滚动条**:占位名册不会滚动,滑块上沿的渐变几行只是近似;超过 12 个角色的滚动没做。
- **按钮悬停/按下帧**:图包里有,界面没有指针跟踪,没用。
- **键位**:方向键与回车、空格、Esc 是按界面形态推的,原版的选角键盘操作没有读到客户端代码。
- **登录**:没有账号、频道、网络;名册只在进程内。真实的登录与角色列表要等 P7(协议)。
