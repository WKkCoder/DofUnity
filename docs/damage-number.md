# 伤害数字(M17-c,E-107)

每次命中,命中点上方弹出一个位图数字:先放大成约两倍、200 毫秒里缩回原大小、停住 400 毫秒、再用 400 毫秒向上飘并淡出,一共 1 秒。主角打出去的数是黄色一套,主角挨的数是红橙色一套。本文记**机制(客户端读码)、画法与位置公式、我们的实现**。伤害点数本身来自伤害流水线(`docs/hit-pipeline.md`),这里只管"怎么显示";不记任何具体数值。

证据等级:生成函数的参数、数字套与动画模板的选择、五个关键帧、位置公式、数字拼法来自静态读码(高);数字图帧与基线逐像素一致、缩放与上飘的时间点与基线吻合(高);水平居中的缩放中心与竖直位置由基线像素反推,落在公式给出的范围内(中);其余调用点的标志、暴击叠加效果没追(低)。没有运行客户端。

## 1. 生成函数与构造函数(E-107)

- **生成函数 0x007f9610**:cdecl 六个参数 `(所有者, x, y, z, 数值, 标志)`。调用点的反编译参数表不可信(延迟清栈),以反汇编里的压栈为准。
- **构造函数 0x007f9160**(this call,`(数值, 标志)`):把绝对值夹在 9999999;把十进制各位依次画进一张池化的 128 × 32 渲染贴图;图源是 `Sprite/Common/Etc/Combo_Big.img`(加载器 0x00759780 的图包顺序里第 0x5c 项);**相邻两位的推进量 = 这一位的帧宽 − 6,数字 1 是 − 5**;各位推进量之和记作总宽 W。
- 动画对象由 0x0109c000 一族建,共五个元素(每个 0xd4 字节):+0x60 停留毫秒、+0x18 与 +0x24 缩放、+8 竖直偏移、+0x2c ARGB 染色、+0x4c "向下一帧插值"开关(与 `.ani` 的帧属性是同一套机制,E-030)。构造函数给五个元素都写 `+4 = −(W >> 1)`(水平偏移)与 `+0xc = 贴图`;生成函数把对象位置设成 `(x − (W >> 1), y, z)`。
- 所以贴图左边在对象位置再往左 `W >> 1`:数字串的"推进宽度"以命中点横坐标为中心(最后一位多出来的几个像素让墨迹中心偏右约 3 像素)。

## 2. 标志位 → 数字套与动画模板

`Combo_Big.img` 里每套数字十帧("0" 到 "9" 顺序排),帧偏移全是 0,数字宽约 20 像素(1 窄一些)。构造函数按标志取套:

| 优先级 | 条件 | 这一套的 "0" 所在帧 | 颜色 |
|---|---|---|---|
| 1 | 位 0 | 143 | 黄 |
| 2 | 位 1 | 54 | 红橙 |
| 3 | 位 3 | 74 | 青 |
| 4 | 位 2 | 数值为负 44,为正 64 | 灰白 / 绿 |
| 5 | 都没有 | 44 | 灰白 |

动画模板:位 4 → 模板 1(暴击,另外在数字上挂 `Common/HitEffect/Animation/CriticalHit.ani`);否则 `(标志 >> 4) & 2` 为真 → 模板 2(缩放固定 1.2);否则模板 0。

命中处理的**主调用点**(0x00e63255 一带)的标志 = `(施加者是本机主角 ? 1 : 0) | (受击者是本机主角 ? 2 : 0) | (暴击 ? 0x10 : 0)`;主角打怪是黄色、怪物打主角是红橙色,两个方向走同一段代码。其余调用点(0x00e2a750、0x005276d0、0x00805570、0x00895b80、0x008b69b0、0x008ba9d0、0x008bbac0、0x00981f20、0x0098d090、0x009a1990、0x00a5d990、0x008bcda0、0x00896780)用到 0x20、8、4、0,**各自对应哪类事件是推断**(状态伤害、魔法值、恢复一类),没有逐个追。

## 3. 动画:五个关键帧

带"插值"开关的帧在停留时间内从自己的值**线性**过渡到下一帧的值,不带的停住。

| 模板 | 帧 0 | 帧 1 | 帧 2 | 帧 3 | 帧 4 | 总长 |
|---|---|---|---|---|---|---|
| 0(普通) | 200 毫秒,缩放 2.0 → 1.0,插值 | 400,停住 | 200,偏移 0 → −39 且 alpha 255 → 128,插值 | 200,偏移 −39 → −69 且 alpha 128 → 0,插值 | 末帧 | 1000 毫秒 |
| 1(暴击) | 同上,停留是 1.5 倍:300 | 600 | 300 | 300 | 末帧 | 1500 毫秒 |
| 2(固定缩放) | 缩放始终 1.2,停留同模板 0 | | | | | 1000 毫秒 |

常量:缩放 2.0 在 0x01562188,1.0 在 0x015620fc,1.2 在 0x0156a55c;偏移 −39、−69 与 alpha 0x80 → 0 是第 3、4 帧里的立即数。alpha 是整个数字的不透明度。缩放的中心是对象位置(水平居中、竖直在贴图顶边),双线性过滤。

## 4. 位置

主调用点(0x00e63255 一带):

- x = **相交盒中心 x** + `rand % 20` − 10;
- y = **受击者自己的 y**(虚函数 +0xa8,无参数);
- z = **相交盒中心 z** + `rand % 20` + 60(0x3c);
- `rand` 是客户端的全局随机数 0x00e50e60(0),非负;
- 盒中心的三个辅助函数 0x0109de20、0x0109de80、0x0109dee0 都是 `(int)(尺寸 × 0.5f + 下界)`(单精度,向零取整);
- 相交盒的语义见 `docs/hit-pipeline.md` §3(E-058):各轴下界取较大、上界取较小;外层是攻击框、内层是受击框,取第一对相交的。

屏幕位置按城镇的加法模型投影对象位置:屏幕 x = 世界 x − 相机 x,屏幕 y = 世界 y − z + 地面;贴图左边再往左推 `W >> 1`,顶边在对象位置的屏幕 y。因此数字的顶边在受击者脚下点上方 z 像素,z ∈ [中心 z + 60, 中心 z + 79]。

## 5. 我们的实现

- `Dnf.Game`:`Aabb.Intersection`(相交盒)与 `CenterX/Y/Z`(客户端的取整法)。
- `Dnf.Play` `DamageNumber.cs`:
  - `DamageNumberFlags`:标志位常量、`FirstFrame(标志, 数值)`、`Template(标志)`;
  - `DamageNumberAnimation`:三条模板的五个关键帧、`TryPose(模板, 年龄)`(线性插值,alpha 四舍五入,播完返回 false)、`DurationMs`;
  - `DamageNumberArt`:按推进规则把各位叠成一张贴图(四周各留 1 个像素透明边,放大时边缘能淡出)、预先双线性放大成帧副本(缩放量化到 1/32,按内容缓存)、`Place` 把一个 `HitPopup` 放到屏幕上(叠加层大类 `OverlayArt.DimRank`:盖住场景精灵、在血条与底栏之下)。
- `RoomCombatSession`:`TryHit` 返回相交盒;命中时按盒中心、受击者 y 和抖动放一个 `HitPopup`(数值、标志、世界位置、模板、寿命 = 模板总长);每个数字活到动画播完;图包里没有 `combo_big.img` 或缺帧时退回 5×7 点阵占位文字(按同一条动画的偏移与不透明度)。
- 受渲染模型限制:覆盖层精灵没有缩放,所以放大是**预先算好的帧副本**;Unity 端按帧对象缓存纹理,缓存有上限。
- 抖动用会话自己的伪随机数(按种子可复现),范围与原版一致,序列与原版不同。
- 命令行:`dnf combat-check` 的命中行与"主角被打中"行都打印 `[数字 值 标志 世界 (x,y,z)]`。

## 6. 与基线的对照(本机一次性测量,非 REA,不入库)

基线 S07(三段普通攻击)的逐帧截图:

- **位图字**:基线上稳定大小的黄色数字,用 `Combo_Big.img` 第 143 帧起一套按 §1 的推进规则叠出来,黄色像素与基线逐个一致。
- **缩放**:同一个数字相隔约 100 毫秒的两次测量(缩放约 1.76 与 1.25)与线性插值吻合;缩放中心的水平位置与竖直位置由放大中的数字边界反推,是对象位置(水平居中、顶边)。
- **上飘与淡出**:约 640 毫秒时已上飘约 9 像素,与模板 0 一致;之后继续上飘并淡出。
- **位置**:两个数字的顶边与各自受击者脚下点的距离、水平位置都落在 §4 的范围内(误差几个像素)。

## 7. 没读通 / 没做

- **暴击**:模板 1 做了,但"暴击"本身还没有(伤害流水线没有暴击),`CriticalHit.ani` 叠加效果没做。
- **其余调用点**的标志与位置公式(§2 列的 13 处)没有逐个追;状态伤害、魔法值、恢复类的数字目前没有来源。
- **抖动的随机数**:原版用全局的 0x00e50e60 一条流,我们用自己的流,位置的具体抖动值不会逐帧一致。
- **双线性的细节**:GPU 采样与我们预放大的帧副本之间的亚像素差别;放大中数字边缘的颜色细节没有逐像素核对。
- **多个数字的先后顺序**:同一帧里多个数字的叠放次序按创建顺序(先放的在下),原版的绘制排序没读。
