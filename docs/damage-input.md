# 主角打怪物的伤害输入(M18,E-110)

主角这一击打在怪物身上,客户端在命中时把攻击信息(`.atk`)、攻击者的面板、防御者的面板填进一个 0x1FC 字节的伤害结构,再交给已经移植好的伤害公式(`DamageFormula`,E-049)。本文是"填的是什么、从哪来、我们怎么接"。接上之后,主角打怪物不再用固定常数的占位伤害(`PlaceholderDamage`,E-069、E-076),而是按攻击信息、面板和怪物防御算出:物理/魔法、防御减免、元素抗性、暴击(数字用暴击那一套)、低等级怪物挨的第一击算额外命中。

证据等级:填充函数的字段对应、额外命中规则、攻击者与防御者的读法来自静态读码(高);技能伤害的两列换算、暴击属性的单位、面板数值的取法是推断(中,和本机基线录像里的读数对过,落在算出的分布里;数值按规则不入库);等级成长、属性点、装备的其余加成没读通,面板只对一级的新角色成立(明确没做)。本文不含原版数值。

## 1. 谁填:命中时的伤害计算槽(E-110)

- **填充函数 0x0087b870**:活动对象虚表的 `+0x388`("伤害计算"槽)。`this` 是防御者,参数里的攻击者/伤害对象是另一个对象。它做三件事:从攻击信息记录取字段、调攻击者的一串读属性槽、调防御者的读属性槽;全部填进伤害结构后调公式(E-049)。
- 客户端初始化伤害结构给的默认值**不是中性的**(`DamageVariables` 的构造函数照搬了这些默认值)。填充函数没有给来源的项,实现里补成"没有加成"的中性值:种类百分比与额外倍率 0、最终百分比 100、威力百分比 100(防御者槽 `+0x3a0` 的缺省)、防御百分比 0、技能暴击与召唤物暴击属性 0。
- 攻击信息不是从 `.atk` 文件现读的:`.atk` 加载器(0x012d9d40)在读脚本时把各标签写进记录,命中时只读记录。最终百分比和技能暴击率的记录**没有**任何 `.atk` 标签写入,所以按缺省(中性)处理。

## 2. 攻击信息 → 伤害结构

| `.atk` 标签 | 记录偏移 | 伤害结构字段(偏移) |
|---|---|---|
| `[damage]` | 浮点 | 基础伤害(+0x00) |
| `[attack type]` | +0x30 | 攻击种类(+0x05):物理、魔法、无视防御 |
| `[weapon damage apply]` | +0x3c | 是否加附加基础值(+0x04);为真时基础伤害再加上攻击者的装备攻击力,随机幅度用第二等级 |
| `[damage bonus]` | +0x2c | 百分比加成(+0x06) |
| `[absolute damage]` | +0x20 | 固定值加成(+0x0F) |
| `[critical hit]` | +0x70 | 暴击率加成(+0x13) |
| `[ignore defense]` | +0xd0 | 跳过防御(+0x0E) |
| `[elemental property]`(列表) | 元素集合 | 四个元素标志(+0x0A..+0x0D);带元素的项取"防御者抗性 − 攻击者元素攻击"(+0x7F 起) |
| `[human damage rate]` | +0x29c | 条件百分比 0(+0x1F),开关 +0xD3 |
| `[fort damage rate]` | +0x2a8 | 条件百分比 1(+0x23),开关 +0xD4 |
| `[monster damage rate]` | +0x2b4 | 条件百分比 2(+0x27),开关 +0xD5 |

三个"伤害率"按防御者身上的状态记号(0x14、0x15、0x16 号)选开关:没有特殊状态的普通怪物只有第三个开关为真,所以 `[monster damage rate]` 对普通怪物生效。记号的含义没读通(推断:人类、要塞、其余;未验证),实现里写死"普通怪物"。

主角的普攻(三段连招、奔跑攻击、空中攻击)的攻击信息都是 `[weapon damage apply] 1` 加 `[damage bonus]`,没有 `[damage]`,伤害全靠装备攻击力与面板攻击力;鬼斩一类技能的攻击信息本身没有 `[damage]` 与 `[damage bonus]`,这两项由技能状态函数按技能脚本的等级表写进去(下面第 5 节)。

## 3. 攻击者与防御者

- **攻击者**:读属性槽 `+0x23c`、`+0x240`、`+0x244`、`+0x248`、`+0x24c`、`+0x250`、`+0x254`、`+0x258`、`+0x260`,依次是物理攻击、物理附加基础值、物理百分比、物理附加次数、魔法攻击、魔法附加基础值、魔法百分比、魔法附加次数、额外倍率(都是整数,进结构时转成浮点)。属性在对象里存成"整数 + 浮点倍率"的记录,读取函数(受保护的 0x011a0de0)返回"整数 × 倍率"向零取整的结果。暴击属性、等级与第二等级也在这一串里。
- **防御者**:防御力是同一种记录(防御力下限夹在 −1500),元素抗性四项、等级(槽 `+0x38c`)、威力百分比(槽 `+0x3a0`)。怪物的这些数取自 `MonsterAbility` 算出的 `MonsterStats`(服务端 `ActiveStaticInfo` 布局,E-062、E-063):整数后面紧跟浮点倍率,乘积向零取整(`DefenderPanel.FromMonster`)。
- 防御者是怪物(对象类型码 0x211,带"活动对象"位 0x11,不带"角色"位),所以公式里防御率、元素折算套用,"防御者的主人是角色"那一段 26 个类型倍率不套用。

## 4. 额外命中(BonusHit)

填充函数的末尾:**防御者等级(槽 `+0x38c`)低于 50,且这一击的攻击者(所有者)不是防御者上一次挨打时记下的那个**,就置额外命中位、命中计数加 1(封顶 4);公式里再乘 1.1(E-049)。

"记下的那个"在防御者的"受击后"槽(`+0x2e0`,函数 0x008711b0)里写:时间、最后的攻击者所有者(对象偏移 `+0x5f4`)、最后的伤害对象;对象初始化(0x00873fb0)时清零,销毁(0x0087de30)时清除。所以**一个低等级怪物被同一个主角连续打,只有第一下算额外命中**。我们的实现在怪物身上记 `LastAttackerId`,主角打中之后写 `RoomCombatSession.HeroAttackerId`。

## 5. 技能伤害的换算(推断)

技能脚本(`.skl`)`[level info]` 当前等级的第 0、1 列是"总倍率百分数"与"固定值"(E-076)。客户端里鬼斩的状态函数用技能的等级数据(`GetLevelDataEx`)给 `[damage]` 与 `[damage bonus]` 赋值。我们的换法(`HitInput.WithSkillDamage`):`[damage bonus] = 倍率 − 100`,`[damage] = 固定值 × 100 / 倍率`——这样 `[damage] × (1 + 加成 / 100)` 恰好等于固定值,装备攻击力那一项按倍率放大;倍率不是正数时只留固定值。

另一种读法(把倍率直接当百分比加成)算出的数比本机基线读数高出一截,被否决。换法本身没有在客户端里逐条核对到赋值指令,所以这一节是推断。

## 6. 面板从哪来:读到了什么、没读到什么

- **服务端**:`CCalcCharacStat::CalcStat`(0x0831ec4a)按 `.chr` 的 `[initial value]` 加每级增量算角色基础属性:1 到 14 级用第一个 `[growtype]` 块,15 到 49 级用所选成长类型的块,50 级起用觉醒段(块布局见 `get_growtype_stat`,0x0834883e)。`_CalcSwordman`(0x0831ed6c)是写死的旧表,不用于这个模型。装备与属性点怎样聚合成属性记录,**客户端里的聚合函数没有找到**,服务端也不核对。
- **我们取的**(`HeroPanel`):面板物理攻击与魔法攻击取 `.chr` `[initial value]` 里第一次出现的 `[physical attack]`、`[magical attack]`,向零取整成整数(比例系数为 1,没有校准常数);附加基础值与暴击属性是主角穿着的所有装备脚本(`.equ`)里 `[equipment physical attack]`、`[equipment magical attack]`、`[physical critical hit]`、`[magical critical hit]` 各取第一个数的加总;元素攻击为 0;等级取 `HeroVitals` 的等级。
- **没做**:等级成长(服务端规则已读到,等有升级再接)、属性点、装备的其余加成、`[equipment …attack]` 后面第二个数的含义、武器 `[separate attack]`(若套用会和基线读数矛盾,保持不用)。所以面板只对一级的新角色成立。

## 7. 实现

- `Dnf.Game/Damage/HitDamage.cs`:`HitInput`(取自 `.atk`:`From(AttackInfoData)`,`FromBonus`,`WithSkillDamage`)、`AttackerPanel`、`DefenderPanel`(`FromMonster`)、`HitDamage`(`BonusHitApplies`、`Fill`、`Roll`)。`Fill` 按第 2、3 节填结构,把没有来源的非中性默认值改成中性;`Roll` 调 `DamageFormula.Compute`,结果至少 1,并返回是否暴击。
- `Dnf.Play/HeroPanel.cs`:`EquipmentStats`(读 `.equ`)、`HeroPanel`(`FromChr`、`WornEquipment`、`ToAttacker`)。
- `RoomCombatSession`:`HeroStrikeInfo.Input` 给出这一击的输入;`Strike` 里**有攻击面板与公式常量时**走 `RollFormulaDamage`(防御者面板取 `MonsterActor.Defense`,没给就按零防御、怪物自己的等级),掷骰种子取自会话的随机序列;暴击时伤害数字带暴击位(E-107,用暴击那套动画);**否则**仍用占位伤害。`Create` 在装配生命与公式常量时一并装配面板与每个怪物的防御面板。
- **回归开关**:`--no-damage`(命令行)与 `-dnfnodamage`(播放器)不装配生命与公式常量,也就没有面板,主角打怪物仍是占位伤害,按时刻对拍的回归检查靠它保持原来的时刻;没有数据的合成试验场同理。
- 命令行:`dnf hero-damage --map <房间>` 对房间里每种怪物、每种招式各掷 N 次,分"第一击(算额外命中)"与"之后"打印最小、平均、最大与暴击占比;数值来自本机的数据,只打印在终端。`combat-check` 的开头一行写明主角打怪物走公式还是占位。

## 8. 核对

- 合成数值测试:Game 33 条(`HitDamageTests`:攻击信息与面板到结构的每个字段、中性化、手算的物理/魔法/防御/元素/暴击/额外命中/随机幅度范围、技能换算、`FromMonster` 的乘积与夹取),Play 20 条(`HeroDamageTests`:装备与面板的读法、`Input` 的来源、会话里"公式/占位"开关、防御减免、暴击数字、额外命中只算第一击、`RollFormulaDamage` 无副作用);全套 1422 条通过(Data 92、Script 7、Squirrel 22、Game 453、Render 274、Play 574),0 警告。期望值都是手算,算式写在测试注释里,没有用原版数值。
- Unity:EditMode 新增 1 条跨运行时核对(`CombatRuntimeTests.HeroFormulaDamage_GivesTheHandComputedValues`:Mono 里算出同一组手算值),共 45 条(35 通过、0 失败、10 跳过——GPU 项在批处理模式下跳过,与之前一致);macOS 播放器对拍 45 帧零差异(含战斗帧:怪物受击、血条、伤害数字、连击)、整局实时流程 16 次阶段切换;Android(IL2CPP)与 Windows(Mono)构建 0 错 0 警告。
- 真实数据:本机用 `dnf hero-damage` 对真实房间算过每段普攻与鬼斩的分布,与基线录像里一级新角色打一级怪物的普攻、鬼斩读数对过,落在分布内(数值按规则不入库)。`combat-check` 在真实房间里跑通:命中、数字、击杀、连击都照常。
- 没有运行原版客户端:这是静态读码加基线录像读数核对。

## 9. 没做与没读通

- 客户端把装备与属性点聚合成属性记录的函数(面板攻击力与暴击属性的真实来源)。
- 技能伤害换算的赋值指令逐条核对、技能等级表的逐级成长、上挑自己的攻击信息与伤害数(现借第三段普攻的)。
- 最终百分比与技能暴击率的缺省(按中性处理)、状态记号 0x14/0x15/0x16 的含义、暴击属性的单位(按百分点)、防御者等级槽是不是等级的最终确认。
- 怪物打主角一侧的额外命中(规则对称,没接;`MonsterDamage` 仍是 E-086 的写法)。
- 等级成长(服务端的 `CalcStat` 规则,等有升级再接)。
