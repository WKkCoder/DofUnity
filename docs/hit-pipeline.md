# 命中与受伤流水线(客户端 `DNF.exe` 的静态读取结果)

一次攻击怎样变成一次命中、伤害怎样落到受击者身上,在客户端里是一条很长的链:**判定 → 几何 → 应用(组包) → 接收端按固定顺序调六个钩子 → 受伤 → 受击反应**。
本文只记**结构事实**:函数地址、虚槽位移、对象字段偏移、代码里的立即数、调用顺序、每一步读什么写什么。都来自对 `DNF.exe` 磁盘字节与反汇编的只读静态阅读,
证据编号见 `docs/evidence/ledger.md` 的 E-056、E-057、E-058、E-060;**不含反编译文本,也不含游戏数据文件里的任何具体数值**。

约定:
- 槽位移 = 槽号 × 4,例如 `+0x2dc` 是第 0xb7 个虚函数。"六个核心类"指 `CollisionObject`、`PassiveObject`、`ActiveObject`、`Monster`、`Character`、`AICharacter`(类表见 `docs/engine-objects.md`;槽实现表由 `tools/py/vslots.py` 从磁盘读出)。
- **观察** = 直接在汇编里看到并核对过;**推断** = 由观察推出;**未知** = 没读到。凡只来自分工阅读卡、没有逐条核对的,标"(卡,中)"。
- 受保护区域(虚拟地址 `0x01dd9000` 到 `0x02c98000`):2026-10-15 起用户授权逆向(E-059)。明文里的受保护**跳板**(`CALL`/`JMP` 进去、很快回来)已经可以用 CPU 模拟器还原成"被偷走的那几条指令"(E-060,工具 `tools/py/emu_stub_probe.py`),文中用"跳板=…"标出;**整个函数体**放在受保护区域里的(角色与 AI 的 `+0x2dc`、怪物 `+0x3a0` 的主体等)仍标"黑盒",只有"从哪里跳进去、传什么、回到哪里"。
- 怪物的数值(血量、攻防、抗性、速度)在服务端由 `set_monster_ability` 按编号、等级、种类现算;规则与我们的移植见 `docs/monster-ability.md`(E-062、E-063)。客户端怎样拿到这些数(收包还是本地也算)没有读。
- "攻击信息"是嵌在每个对象里的一块结构,起点在对象的 `+0x2d4`(槽 `+0x204` 返回它,实现 `0x00442c60`)。后文用"攻击信息 `+X`"表示这块结构内的偏移,对象内偏移 = `0x2d4 + X`。

## 1. 总览

```
攻击方每帧逻辑(调用者在受保护区域,看不到)
   │  tryHit(槽 +0x2b0, 实现 0x0087eb50)          ← 第 2 节:门条件、去重、几何、命中次数
   │     └ 几何:槽 +0x2b4 → 0x00876c00              ← 第 3 节:当前帧的攻击框 × 受击框
   │     └ 受击方槽 +0x3a0 查询:返回 3 = 不能被命中     ← 第 2 节门 7(E-060 更正:没有随机掷骰)
   ▼
applyHit(0x00875de0,cdecl)                           ← 第 4 节:stuck 掷骰、本地钩子、组包 19、发送
   │  send(1,-1,0,3) → 八座位循环 → 本机也收到(推断)
   ▼
HandlePacket(0x00e5fc6d,E-056)的 case 19(入口 0x00e628d4)   ← 第 5 节:按固定顺序调六个钩子
   │  onBeforeAttack → onBeforeDamage → [登记器] → onAttack → onDamage → onAfterAttack → onAfterDamage → [登记器/所有者]
   ▼
受伤:碰撞基类 0x0087a580 / 主动对象 0x00828800 / 怪物 0x0089c7b0 / 角色与 AI 全在黑盒   ← 第 6、7 节
```

另有不走 `applyHit`、也不发包的命中路径:某个被动一族的类(更新函数 `0x00a35500`)自己用槽 `+0x2b4` 做碰撞判定,成功后**直接调受击方的 `+0x2dc`**(观察,E-057)。

## 2. 命中判定 tryHit(槽 `+0x2b0`,六个核心类共用 `0x0087eb50`)

签名:`__thiscall`,`this`=攻击方;参数 1 受击方,2 `applyFlag`(字节),3 命中信息输出指针(可空),4 `extraFlag`(字节);返回命中与否;`RET 0x10`。

按顺序的门(观察,汇编逐条核对;字段含义含推断):

| # | 条件 | 拒绝时 |
|---|------|--------|
| 0 | `applyFlag` 为真,且 `0x007f9eb0` 对攻击方、受击方都为假,且 `extraFlag` 为 0 | 返回假 |
| 1 | 槽 `+0x210`(`0x0087ad70`:这个攻击是否已命中过该目标)为真,且 `+0x3cc` ≠ 2 | 返回假 |
| 2 | **`[attack myself]` 为 0**(攻击信息 `+0x184` = 对象 `+0x458`,受保护整数),且槽 `+0x328` 对双方返回同一个值 | 返回假(不能打自己人) |
| 3 | **`[attack friend]` 为 0**(攻击信息 `+0x190` = 对象 `+0x464`),且受击方字节 `+0x5d8` 为 0,且 `0x00872c60`(队伍是否不同)为假(同队),且双方 `+0x328` **不等** | 返回假(不能打队友) |
| 4 | **`[attack enemy]` 为 0**(攻击信息 `+0x19c` = 对象 `+0x470`),且 `0x00872c60` 为真(异队) | 返回假(不能打敌人) |
| 5 | **几何**:槽 `+0x2b4`(第 3 节),调用前先构造命中信息 | 返回假 |
| 6 | `+0x3cc` == 2:`0x0087ea70` 做同一目标 **1000 毫秒**(`CMP … 0x3e8`)间隔判断(映射在对象 `+0x60c`) | 返回假 |
| 7 | **受击方"能否被命中"查询(E-060 更正:这里没有随机的未命中掷骰)**:调用点先把 100 放进栈上的一个局部,调攻击方槽 `+0x230` 取"实际对象",明文处的 `CALL 0x020ef5a7` 是受保护跳板,**跳板 = 被偷走的一条指令 `MOV EDX,[EBX+0x3a0]`**(此时 `EBX` 是受击方的虚表),随后以受击方为 `this` 调槽 `+0x3a0(&值, 攻击方实际对象)`;返回 3 表示不命中(`CMP EAX,3 / JZ`)。槽 `+0x3a0` 的实现见第 6、7 节与 E-060 | 返回假 |
| 8 | 对象 `+0x454`(= 攻击信息 `+0x180` = **`[max target hit number]`**)> 0 时:已命中数 `+0x814` ≥ `+0x454` 则拒绝,否则 `+0x814` 加 1 | 返回假 |

通过后:若参数 3 非空,把命中信息拷过去(`0x00582330`);若 `applyFlag` 为真,调槽 `+0x20c`(`0x0087e9d0`,登记目标)再调 `applyHit(攻击方, -1, 受击方, &命中信息, 0, 1)`。
`applyHit` 是 **cdecl**(调用后 `ADD ESP,0x18`,函数末尾是不带操作数的 `RET`),第 5 个参数 0、第 6 个参数 1。

几点交叉印证(观察):
- 门 2、3、4 读的三个受保护整数,位置恰好等于 `.atk` 加载函数写 `[attack myself]`、`[attack friend]`、`[attack enemy]` 的位置(第 9 节)。**默认值是只有 `[attack enemy]` 为 1**:攻击信息的"清空"函数 `0x012b83a0` 用一个循环 3 次的循环写这三个值,写入的是"下标等于 2"(汇编里是 `CMP EDI,2` 接 `SETZ`),所以 `[attack myself]`、`[attack friend]` 为 0,`[attack enemy]` 为 1,与 E-047 里 C# 加载器的默认值一致(观察)。
- `+0x3cc` 是攻击信息 `+0xf8`,即 `[hit info]` 写入的第一个字段;值 2 表示"多段命中,每个目标 1000 毫秒一次"。
- `+0x328`:主动一族(`ActiveObject`、`Monster`、`Character`、`AICharacter`)的实现是 `0x00624d80`,和槽 `+0x230` 同一个函数,返回自己;被动对象的实现是 `0x0046fc90`。所以它更像"根所有者"而不是抽象的阵营号:双方相等就是"自己人"。(推断,高)
- 对象之间"队伍是否不同"(`0x00872c60`):比较槽 `+0x22c` 返回的队伍号,特例里出现种类码 `0x111`、`0x1211` 与队伍号 `0xC8`,一个"游戏模式 7"分支改用 `Character+0x522c` 比较(卡,中)。

去重与登记(观察):已命中目标映射在攻击方 `+0x5a0`(键是经槽 `+0x230` 解析出的"实际对象");槽 `+0x214`(`0x00442c70`)返回的就是 `this+0x5a0` 这块结构的地址。
清空入口(观察,E-058):原生接口 `resetHitObjectList` 的实现 `0x005b7000` 只是一个转调,调的是本对象的槽 `+0x208`(六个核心类都是 `0x00443350`),它清两个容器:`+0x5a0`(已命中目标)和 `+0x60c`(多段命中的时间戳表)。
`sq_SetMaxHitCounterPerObject` 的实现 `0x006adf70` 写的是 `this+0xecc` 起的一个受保护整数,**不是**门 8 读的 `+0x454`;所以 `+0x454` 只来自 `.atk` 的 `[max target hit number]`,脚本那个计数器作用在别处(没追到读它的地方)。

**命中分组键**(观察,E-058):每个碰撞体系对象有一个字节集合 `+0x648`。构造后期的 `0x0087fe70` 往里放进一个默认键,取自 rodata 常量 `0x015cdf60`,值为 0,所以**默认每个对象的集合里只有键 0**。
`applyHit` 的第一道校验 `0x00875470` 是 `__thiscall`,`this` 是攻击方、参数是受击方:遍历**受击方**集合里的每个键,问攻击方集合(成员检查 `0x008753f0`)里有没有,有一个就返回真;受击方为空指针或集合为空或没有交集就返回假。
`0x00879a00` 往集合里加一个键;`0x00879a30` 用一个向量整体重设并通知对象管理器(`0x008ae450`);`0x00875a90` 把集合序列化进包(先个数、再逐个字节)。谁会改键、键代表什么**没追到**(推断是"阵营之外的又一层分组",让一部分攻击只能打到一部分对象,低)。

## 3. 几何 `0x00876c00`(槽 `+0x2b4` 的核心;包装体:碰撞/被动类 `0x00879c80`,主动一族 `0x008250a0`)

- 攻击方槽 `+0x364`(攻击框开关)与受击方槽 `+0x36c`(受击框开关,基类实现读受保护整数 `+0x698` 非 0)为假则不命中。
- 框来自**当前动画状态对象**:`0x0043f3f0` 返回的两个向量,`+0x70` 攻击框、`+0x84` 受击框,元素 0x18 字节 = 6 个受保护 float;`ani+0x144 == -1`(缓存没算)时先调 `0x0109c4c0` 刷新(观察,E-058:它重算动画整体范围的缓存并递归到子动画,没有细读)。
- 六个值的顺序是 `(x, y, z, 宽, 深, 高)`:与 `.ani` 磁盘顺序一致;世界平移只加在前三个(槽 `+0xa4`/`+0xa8`/`+0xac` 返回整数,基类实现 `0x00406390`/`0x004063a0`/`0x004063b0`,六个核心类相同,推断分别是 X、Y、Z);
  朝向槽 `+0xf8`(`0x007f9e90`,六类相同)返回 0 表示向左,向左时框镜像 `x' = -x - 宽`。
- 遍历:外层攻击框、内层受击框,**第一对相交就返回真**。相交判断 `0x01090040`(观察,E-058 更正了容差的用法):
  (1) **先要求两个框的六个尺寸(宽、深、高 × 两框)都不为 0**,写法是 `|v| × 2^-23 < |v|`(常量在 `0x01562898`,字节 `00 00 00 00 00 00 80 3e`,**要按 8 字节 double 读**,`f:` 读成 float 会得到 0),这个"容差"只用在这六次非零检查上;
  (2) 然后三个轴各做两次**闭区间**比较:攻击框的 `下界 + 尺寸` 不小于受击框的 `下界`,且受击框的 `下界 + 尺寸` 不小于攻击框的 `下界`(x87 比较,没有容差);任一不满足就返回假;
  (3) 全部满足、且调用方给了命中信息指针时,写出相交盒(下一段)。
- 攻击信息字节 `+0x17d` 为 1(`[hit check by screen pos]`)且对象管理器非空时,攻击方的 Z 先经 `0x00403520`/`0x008a7b80` 修正。
- 我们 P3/P4 在 C# 里用的 `Combat.ToWorld`、`.ani` 框顺序、左向镜像,与这里读到的**一致**(观察+对照)。

命中信息结构(`0x0109d9a0` 构造,0x18 字节,6 个受保护 float)就是**相交盒**(观察,E-058,读 `0x01090040` 的尾部):布局与框相同,`(x, y, z, 宽, 深, 高)`;
位置 = 两个框各轴下界的较大值(`0x0108f610`),尺寸 = 两个框各轴上界(下界 + 尺寸)的较小值减去这个位置;每个值写出前用 `0x011a0a20` 编码。
脚本回调里的 `boundingBox` 参数多半就是它(推断,中:钩子的第二个参数是命中信息,回调签名里同一位置是 `boundingBox`,脚本用它取接触点中心来放命中特效)。

## 4. 应用 applyHit(`0x00875de0`,cdecl,六个参数)

参数:攻击方、攻击信息序号(−1 = 当前,走槽 `+0x204`;≥ 0 走 `0x0070213f`,**没读**)、受击方、命中信息指针、`checkDamagable`(字节)、`allowStuck`(字节)。

1. 前置:攻击方、受击方非空;`0x00875470(攻击方, 受击方)` 校验两边的分组键集合是否有交集(第 2 节末;默认两边都只含键 0,所以默认通过);两个对象各经槽 `+0x230` 解析成"实际对象";`checkDamagable` 为真时调受击方槽 `+0x37c(攻击方)`,返回假就整个放弃(从 `tryHit` 来的调用传 0,不做这个检查)。
2. **stuck 掷骰**(只在 `allowStuck` 非零、受击方 `+0x30(0x11)` 为真即主动对象、攻击信息非空时做;攻击信息取自攻击方"实际对象"):
   ```
   分 = 攻击信息.[stuck](+0x74) + 3.0
   若 攻击信息.[stuck prob increase](+0x80) 非 0:  n = 攻击方槽 +0x214 返回结构的 +0x10;若 n > 1:  分 += n(n+1)/2 − 1
   若 受击方槽 +0x38c < 50 且 受击方槽 +0x390 ≠ 攻击方槽 +0x32c:  分 −= 5.0
   若 0x00871c40(攻击信息方向与受击方朝向相反):  分 −= 5.0
   血量项 = 0;若攻击方槽 +0x224 为真(玩家链):取血量比例(槽 +0x334,或所属者槽 +0x440(3) 里的两个受保护 float 相除)
   血量项 += 受击方槽 +0x4ec(攻击方);若 0x00706410 的模式探测通过:血量项 *= 线性插值(0x00873420 给的 0..10000 的索引 → 0..1.0)
   分 += 血量项;分 ≤ 0 则不掷
   r = 随机数(0x00e50e60(0)) % 10000;若  分 × 100.0 > r:  stuck = 1,攻击方 +0x82c 加 1,受击方 +0x3250 记时间戳(0x008733f0)
   ```
   立即数都已对照磁盘核对:3.0、5.0、100.0、1.0、0.0、10000。公式里的基础项 3.0 对应 3%。随机数是全局 SdcRandom(种子在 `0x01a39ce8`,第一次用时取 `GetTickCount`),与服务端同一个线性同余,C# 里已有 `SdcRandom`。
   `n` 所在的结构同时是第 2 节的命中登记表(`this+0x5a0`),所以 `n` 很可能是"这次攻击已经登记的目标数"(推断,中)。
3. 受保护跳板 `0x008760ba`(`JMP 0x020ef1b6`),明文续接在 `0x008760bf`。**跳板 = 被偷走的两条指令 `MOV EDI,[EBP+0x14]`(命中信息指针)与 `TEST ESI,ESI`(攻击方非空)**(E-060:模拟器里只有它写 `EDI`,标志位只随 `ESI` 是否为 0 变化,其余寄存器与参数怎么改都不变;5 字节正好是 3 + 2)。所以 `0x008760bf` 的 `JZ` 是"攻击方为空就不调攻击方的本地钩子";读到的 stuck 标志是栈上 `[EBP-0xc]`。
4. 本地钩子:攻击方槽 `+0x2c4(受击方, 命中信息, stuck)`、受击方槽 `+0x2c8(stuck, 命中信息, 攻击方)`。
5. 组**类型 19 的包**并发送(第 5 节),发送是 `[0x01add538]` 的槽 `+0x44` = `0x00e5c970`,实参 `(1, -1, 0, 3)`。

**stuck 标志的真实含义(更正,E-057)**:这一个字节之前被叫成"暴击标志",**不对**。依据:
(a) `.atk` 加载函数里 `[stuck]` 写攻击信息 `+0x74`、`[stuck prob increase]` 写 `+0x80`,而 `[critical hit]` 写的是 `+0x68`(第 9 节,由脚本复现);
(b) 脚本回调 `onAttack`/`onDamage` 等的签名是 `(obj, 对方, boundingBox, isStuck)`,正好对应钩子的 `(对方, 命中信息, 标志)`;
(c) 存在原生接口 `sq_SendHitObjectPacketWithNoStuck`,与"第 6 参数为 0 时不掷"吻合;
(d) 标志为真时碰撞基类的受伤函数**不扣血**,而是调槽 `+0x39c`(`0x0087b620`)生成 `Common/HitEffect/Animation/Stuck.ani` 与 `Character/Swordman/Effect/Animation/Guard/Spark.ani` 两个特效,并按攻击信息 `+0xfc` 播 `STUCK_BLUNT` 或 `STUCK_BLADE`。
游戏里的确切含义(受击硬直?被"卡住/挡住"?)**未定**;只能确定:它是 `.atk` 里 `[stuck]` 那组字段驱动的、与伤害数值无关的一次掷骰。全库 `.atk` 里 `[stuck]` 绝大多数为 0。
`EtcParameter.etc` 里另有名为 `[stuck rate]` 的参数块(数值不入库),是否由这里读取**未追到**。
真正的暴击不在这里:服务端公式里的暴击判定(`checkIsCriticalSDC`,E-049)是另一回事。

## 5. 类型 19 的包与接收端

包(UDP 模块 `[0x01a6f748]` 的写入器;开始一个包是槽 `+0x08`(`0x00e5b5f0`),参数 `(2, 19)`;写 1 字节槽 `+0x20`,写 2 字节槽 `+0x24`,写 n 字节槽 `+0x34`;包头 7 字节,载荷从 `+7` 起):

| 序 | 宽 | 内容 |
|----|----|------|
| 1–2 | 2+2 | 攻击方的两个同步编号(槽 `+0x44`、`+0x48`) |
| 3–4 | 2+2 | 受击方的两个同步编号 |
| 5 | 4 | 命中信息 +0x00(经 `0x011a0ab0` 编码) |
| 6–10 | 2×5 | 命中信息 +0x04 到 +0x14:各自 `0x011a0ab0` 后转整数(`CVTTSS2SI`,向零截断),取低 16 位 |
| 11 | 1 | stuck 标志 |
| 12 | 2 | 第二次 `0x00e50e60(0)` 的低 16 位(与 stuck 掷骰独立;接收端存起来参与后面的算术,推断为校验用的盐,低) |

`0x011a0ab0`/`0x011a0a20` 是**字节置换表**(表在 `0x01851b00`/`0x01851a00`,按字节位置再偏移)的编码/解码,**不是线性量化**;联网实现(P7)才需要它。

**这个函数里的 `+0x1a4` 不是血量**(更正,E-057)。`+0x164`(`0x007fdf90`)把 `+0x1a4` 设为第 1 参数(第 1 参数非 0 而第 2 参数为 0 时强制为 0),
并在第 1 参数非 0 时记 `+0x1a8 := 第 2 参数`、`+0x1ac := 现在 − 第 3 参数`;配套的三个读取槽是 `+0x170`(`0x00406690`)= 现在 − `+0x1ac`、`+0x174`(`0x004066b0`)= `+0x1a8`、`+0x178`(`0x004066c0`)= `+0x174() − +0x170()`。
也就是说它是一个"状态值 + 记录量 + 起点时间戳"的带时间的状态,剩余量 = 记录量 − 已过时间。这里伤害被当成记录量写进去,确切含义**未定**(多半是某类可被打坏的物件的计时状态)。
第 1 参数从 ≥ 1 掉到 < 1 或反向时,基类还会切 `.act` 子对象的启用标志,主动对象调槽 `+0x5a4`(推断:死亡/复活入口),并调全局 `0x011babf0`/`0x011bab70` 与依附体通知 `0x008b06b0`。

**结论(观察)**:这个函数**只读** `+0x108`,不在这里算伤害公式,也不扣怪物或玩家的血。伤害公式(服务端的 `computeHpDamageSDC`,E-049,"SDC" 推断为服务端与客户端共用的一份代码)在客户端的位置**读不到**,
候选是受保护跳板;所以 C# 里的做法是:命中时按 E-049 的公式算好一个整数写进"攻击信息的最终伤害",再让受伤流程只消费它。

**更正(E-076,推断,高)**:上面把攻击信息 `+0x108` 叫作"伤害"、把 `+0x164` 叫作"不明的计时状态"都应改:
(a) 脚本接口 `sq_SetCurrentAttackeHitStunTime` 的实现 `0x005b8290` 把第 2 个参数写进攻击信息 `+0x100` 起的受保护记录(值在 `+0x108`)——正好是这里读的那个整数;
(b) 脚本接口 `sq_SetPause` 的实现 `0x005adcd0` 转调对象槽 `+0x164(参数 1, 参数 2, 0)`,与这里 `+0x164(1, +0x108, 0)` 同一个调用形状;`sq_IsPause`/`sq_GetPauseType`/`sq_AnimationSetPause` 在同一组;
(c) 读取槽的"剩余 = 记录量 − 已过时间"只有当记录量是**毫秒时长**时才说得通;「若已在暂停且剩余更短才覆盖」(上面的两个分支)就是"取更长的定身时间"。
所以 `+0x164` 是**对象暂停**(类型、时长、起点),`+0x108` 是**受击停顿的毫秒数**,这个函数的作用是"受击方被定住这么多毫秒"(怪物那个按难度档做的除法很可能是 `.mob` 的 `[stun time balance]`)。**伤害数值本身不在这里,出处仍未找到**。
这一条没有用运行时取值验证(受击方 `+0x2a0`、怪物表项与 `+0x108` 的运行时值都不在明文区域)。攻击方被定住的位置见本节末的 E-077 补全。

**补全(E-077,静态读码,没有运行时验证)**:
- **攻击方也被定住**:碰撞基类 `onAttack`(槽 `+0x2d0`,`0x008774e0`)读同一个 `+0x108`(对象内 `this+0x3dc`),字节 `+0x2a0` 非 0 且毫秒 > 0、并且(当前没有暂停,或暂停类型 1 且剩余 < 毫秒)时调 `+0x164(1, 毫秒, 0)`;主动对象的 `onAttack`(`0x0081d8f0`)在遍历完 26 个模块槽后于 `0x0081dab6` 调它,角色的 `onAttack`(`0x0084a570`)又调主动对象的。所以一次命中里,攻击方与受击方各自定住**同样的毫秒数**,各自"长者胜"、不叠加。
- **暂停冻结什么**:当前动画(`[this+0xc0]`)、`[this+0x12c]`、依附体树(`0x008b06b0`)与子动画链(`this+0xc4`);结束时恢复到暂停前保存的状态(字节 `+0x1b0`)。对象的位移与状态计时是否一并停,没有读(推断为停)。
- **毫秒从哪来**:`.atk` 的 `[hit info]` 整数项(默认 −1);−1 或没有 `[hit info]` 就取角色 `.chr` 的 `[weapon hit info]` 里这件武器那一项(下标 = 装备脚本的 `[sub type]`);写了 `[is use weapon hit delay rate]` 时改为"武器的停顿 × 文件里的整数";最后大于 0 的结果乘 `(2.0 − 属性)`,属性在属性组(下标 3)的 `+0x528` 记录里、复位值 1.0,所以默认系数是 1。这些发生在角色槽 `+0x200`(`0x0084a1a0`)里,它在把共享的 `.atk` 模板拷进对象当前攻击信息(`0x008185c0`)前后暂存并还原模板,所以共享模板不会被改。
- **对 Unity 的含义**:鬼斩、上挑、三段普攻的 `.atk` 都没有 `[hit info]`(或写 −1),停顿全由武器表决定;换武器就换停顿。`HitStop.StunMs`、`RoomCombatSession`、`MonsterActor.Pause` 照此实现。受击方的反应时长(槽 `+0x388`、怪物槽 `+0x3a0`、`.act` 的 `[HIT DELAY]`)仍是占位。

怪物的 `+0x2dc`(`0x0089c7b0`,4593 字节)在调用 `0x00828800` 之前做仇恨、击退表现(槽 `+0x134`)、受击触发器表等(卡,中);它最开头的**抓取判定**已读(观察,E-058):

1. 读自己的 `curHp`(槽 `+0x2a4`)与 `maxHp`(槽 `+0x2a8`),调 `0x00879760`(`this` = 受击怪物,`RET 0x14`),参数依次是 攻击方、`this+0x254`、`curHp`、`maxHp`、常数 1。第 5 个参数 `1` 在调用点比两个血量读取更早压栈,而且两个读取槽都不带参数、不弹栈,所以它留在了栈上;读汇编时要当心别数错参数个数。
2. `0x00879760` 取攻击方的攻击信息(槽 `+0x204`),遍历它的 `[catch object]` 列表(攻击信息 `+0x2b8` 起的一个有序容器,每项 12 字节:两个整数加一个 float)。一项**全部满足**才算抓到:第一个整数等于 1(第 5 个参数)、第二个整数等于受击方 `+0x254`、且 `curHp × 100.0 / maxHp ≤ 第三项`。
   抓到时:攻击方 `+0x2ac` 写 1,受击方字节 `+0x2a8` 写 1,返回真。第一个整数对上、第二个整数对上但血量比例不够时,若攻击方 `+0x2ac` 不是 1 或 2 就写 2;第二个整数对不上时,若 `+0x2ac` 不是 1、2、3 就写 3(推断 2 = 血量还不够、3 = 不是可抓的怪物,低),然后看下一项。
3. 返回真之后:受击方 `0x007f9eb0` 为真(推断是"这台机器拥有该对象",与 tryHit 的门 0 同一个函数)时,调槽 `+0x30c(12, 0, 3, 0, 0)` 与槽 `+0x318()`(这两个槽在原生注册表里的名字是成员函数 `addSetStatePacket` 与 `flushSetStatePacket`,即脚本里 `obj.addSetStatePacket(…)` 那一族:"请求切换状态"与"发出请求"),然后**整个函数返回**,不再走后面的受击流程,所以被抓住的怪物这一击不扣血。
   状态号 12 在脚本枚举头里是 `STATE_UNSUMMON`(被"逆召唤"而消失);所以抓取成功的效果是怪物进入这个状态消失(推断,中:状态名来自脚本头,"抓取 = 逆召唤"的解释是我们的)。
4. `+0x254` 在怪物上是怪物编号的可能性很大(推断,中):`0x00890350` 开头把它当键,去一个全局管理对象里查表;`0x00891650` 比较两个怪物的 `+0x254` 是否相同。
   在全库 `.atk` 里带 `[catch object]` 的极少,看到的条目第一个整数都是 1,第二个整数是五位数的编号,第三项是一个不大的百分数;与上面的判定吻合(数值不入库)。
5. 抓取成功后的状态号、`+0x2ac` 的三个值由谁读取(猜想是 `.act` 或脚本侧的抓取技能),**没追到**。

后面的明文主体(时间窗冷却 `timeGetTime() < this+0x50d4 + this+0x50d8`、`+0x3658` 为 3 或 8 时调槽 `+0x750`、`this+0x4824` 一带 0x14 字节一项的向量、70% 概率的槽 `+0x84c` 等)只做了粗读,含义大多未定。

## 10. 对 Unity 实现(P5)的含义

1. **几何、顺序、命中次数、敌我门**是明文,可以按本文直接实现并写测试(测试用合成数据,不用原版数值)。敌我门直接用 `AttackInfoData` 里的 `[attack myself/friend/enemy]`。
2. **stuck**:按第 4 节的公式实现,标志只影响"是否走碰撞基类的特效/音效、不扣血"和脚本回调的 `isStuck` 参数;**不要**把它当暴击。tryHit 里**没有**"未命中掷骰",只有受击方"能否被命中"的查询(槽 `+0x3a0`,返回 3 = 不能命中):Unity 里对应"无敌/免疫状态"的判断,按公认语义先实现为布尔。
3. **伤害数值**:按 E-049 的公式在命中时算好,写进攻击信息的"最终伤害";受伤流程只消费它,并按人数/难度档对怪物做整数除。
4. **六个钩子**:实现成一个事件序列(第 5 节表),把 `onBeforeAttack`…`onAfterDamage` 六个脚本回调挂在上面;世界闩 `+0x24/+0x25/+0x28` 只在需要时再做。
5. **HP 与死亡**:黑盒里的扣血按公认语义实现(HP ≤ 0 即死),再靠基线录像(阻塞中)或联机对照核对差异;不要照搬 `+0x1a4`。
6. 联网同步(P7)才需要包 19 的字节布局与置换表;单人不需要模拟 UDP。

## 13. 受击反应:状态请求在哪里发出(E-078;静态读码)

**结论先说**:对象被打中后进入受击、倒地、死亡,是通过槽 `+0x30c`(`addSetStatePacket`,实现 `0x008779b0`)请求脚本枚举里的 `STATE_DAMAGE`、`STATE_DOWN`、`STATE_DIE`;请求发在主动对象受伤函数 `0x00828800` 的**尾部**(这个函数比第 5 节写的长,一直到至少 `0x00829cf0`)。
硬直时长、击退速度与倒地时长**不在发请求的地方**,在这些状态"开始"之后的处理里,那一段**还没找到**(Unity 里的 `HurtHoldMs`、击退缓动、倒地停留仍是占位值)。

| 请求 | 位置 | 形状与观察 |
|------|------|-----------|
| `STATE_DAMAGE`(3) | `0x008297a2` | `(3, 参数列表, 优先级 3 = STATE_PRIORITY_FORCE, 0, 0)`;受 `this+0x322c == −1` 守卫 |
| `STATE_DOWN`(4) | `0x00829aee` | 触发条件没读 |
| `STATE_DIE`(5) | `0x00829b86` | 触发条件没读 |

DAMAGE 请求的参数列表(顺序,观察):

1. 攻击方槽 `+0x3e4(受击方)` 的返回值(原样放进去,类型没定);
2. 一个整数:受保护的全局 float 乘以一个局部 float,向零取整;
3. 一个局部量(来源没追);
4. 攻击信息 `+0xf8`(`[hit info]` 的第一个字段,即命中模式);
5. 攻击方的所属者(槽 `+0x32c`)的属性组 3 里取的一个值(没有所属者时为 0;属性组访问槽 `+0x440`、取值函数 `0x004c1c80`,没追完);
6. `[force hit stun time]`(攻击信息 `+0x138` 记录的值);
7. 仅当 `[knuck back]`(`+0x8c` 记录)的值不为 0:放进这个值;
8. 仅当该值等于 3:再放进 `+0x98` 记录的值。

**击退距离(`[push aside]`)与浮空高度(`[lift up]`)不在这份受击(DAMAGE)列表里**(E-079 更正:它们在倒地(DOWN)列表里,见第 14 节);受击状态的"开始"处理是不是自己去读攻击信息,没查;`.atk` 里这几项仍然是 Unity 实现需要的输入。
参数各项对应哪个标签是观察(偏移与第 9 节的标签表对得上);各项的运算与消费者是推断,没读。

**与怪物相关的另外两处观察**:
- 怪物每帧函数 `0x00896780`(到 `0x00899516`)里有两次请求(`0x00899319` DAMAGE、`0x0089940d` DOWN),作用在 `this+0x396c` 指向的另一个对象上,随后清零这一带:推断是"放开抓着的对象"(中)。
- 怪物对象 `+0x388c` 是个整型,被打成 0x18 字节的同步包(`0x008805a0` 发送、`0x00880640` 接收),基类里本地只在重置 `0x0089e990` 写 0;`+0x5a8`(`0x00881430`)在它为 0x16 时返回假。(E-079 更正:当前状态号的字段是 `this+0x3094`,不是它;它与 `STATE_*` 枚举没有对应关系的证据。)
- 服务端符号表里 `Monster`、`CMonster` 没有受击、击退、倒地、移动的方法(推断,中:怪物行为由客户端模拟,服务端只做伤害校验与掉落)。

**下一步入口候选**:`flushSetStatePacket`(`0x00879db0`)之后的状态应用;主动对象每帧函数 `0x00834760`(里面有 `STATE_DOWN` 请求,槽加载处 `0x00834ac5`、`0x0083587c`;已读过结构,见第 14 节);`0x008360e0`(约 3266 行,主动对象跳跃、下落、倒地阶段的状态机,`STATE_DOWN` 请求在 `0x008362ea`,倒地音效按重量分三档)。

## 14. 受击反应:"请求哪个状态"的决策(E-079;静态读码)

**结论先说**:被打中后请求 DAMAGE、DOWN 还是 DIE,由主动对象基类虚表的 `+0x504`(实现 `0x00822ca0`,几百个派生类共用)一次决定;它读攻击信息的 `[damage reaction]`、`[ignore super armor]`、`[push aside]`、`[lift up]`、`[knuck back]`、`[bounce]`,再看受击方的当前状态、有没有受击/倒地动作、是否已死。**时长、击退速度、倒地停留不在这个函数里**(它只返回状态号),仍是占位值。

决策顺序(观察;每个分支逐条核对过,"推断"处另注):

| 步骤 | 条件 | 结果 |
|------|------|------|
| 1 | `[damage reaction]` = 0 | 不产生反应 |
| 1' | `[damage reaction]` = 3(Unity 的 `DamageExceptHuman`)| `0x0052e870(受击方, 0x14)` 为真 → 不产生反应;为假 → 按 1 处理(推断:前者是"受击方是不是人类"一类的类型判断) |
| 2 | 算"霸体模式"m | `this+0x6a4` 的受保护整数非 0 取 `this+0x6b0`,否则取 `0x007fbb10(this)`;槽 `+0x3a0(&100, 攻击方)` 返回 1 或 2 且 m ≠ 2 → m = 1;m = 1 且 `[ignore super armor]` 非 0 → m = 0 |
| 3 | **已死** | 槽 `+0x508`(怪物 `0x0081f170`):当前状态已是 DIE → 不产生反应;怪物有倒地动作 → **DOWN**;没有 → **DIE**(例外:标志为真或当前状态为 9、且槽 `+0x728` 为假 → DIE;类型标志 `0x111` 的对象 → DOWN) |
| 3' | 选了 DIE | 输出一(死亡变体)= `[push aside]` < 150 且 `[knuck back]` 类型 ≠ 1 ? (`[lift up]` < 400 ? 2 : 5) : (攻击方槽 `+0x3e4(受击方)` 非 0 ? 3 : 4)。150、400 是引擎代码里的常数 |
| 4 | **没死**,m ≠ 0 | 只有满足例外条件才继续(受击方字节 `+0x738` 一带的两个检查加攻击方槽 `+0x220()`;或怪物的 `[+0x3918]` 所指对象标志加 `+0x220()`),否则不产生反应;m = 0 直接继续 |
| 5 | 槽 `+0x540(1)` 或 `+0x540(7)` 为真(异常状态 1 或 7) | 不产生反应 |
| 6 | `[damage reaction]` = 2 | 倒地分支 |
| 6' | `[damage reaction]` = 1 | 槽 `+0x26c()`(`this+0x274`,推断:霸体等级)> 0 或槽 `+0xac()`(推断:高度)≤ 0 → **当前状态是 DOWN 走倒地分支,否则走受击分支**;`+0x26c()` ≤ 0 且高度 > 0 → 倒地分支 |
| 7 | 倒地分支 | 有倒地动作 → 4(DOWN);此时若当前状态已是 DOWN、`this+0x3340` ≥ 1、`[bounce]` = 0 → 输出二 = 1;没有倒地动作 → 退到受击分支 |
| 8 | 受击分支 | 有受击动作 1 或 2 → 3(DAMAGE);都没有 → 不产生反应 |

**倒地(DOWN)请求的参数列表**(`0x00829aee` 处,五项,观察):① 攻击方槽 `+0x3e4(受击方)` 的返回值;② 决策函数的输出二;③ "倒地类型"0 到 3(`[bounce]` 非 0 且输出二为 0 时 = `[ignore weight]` 非 0 ? 2 : 3,否则 = `[ignore weight]` 非 0 ? 0 : 1;即"弹起"与"受体重影响"两位);④ `[push aside]`;⑤ `[lift up]`(局部布尔为真且类型 ≠ 0 时再加 50;布尔来源没追)。随后 `(4, 列表, 3, 0, 0)`,守卫 `this+0x322c == −1`。基类每帧函数 `0x00834760` 里,对象已死、当前状态与待处理状态(`this+0x66c` 一带)都不是 DOWN、DIE、9、12 时会再请求一次:有倒地动作 → DOWN,列表是 4、0、1、400、400(引擎常数,对得上上面五项:无攻击方、输出二 0、类型 1、默认击退 400、默认浮空 400);没有 → DIE,列表怪物类 [2]、类型标志 `0x111` 的 [0]、其余空。

**第二处 DAMAGE 请求**:`0x00823630`(两个参数)在受击方字节 `+0x3228` 非 0 且槽 `+0x378()` ≠ 1 时累计伤害 `+0x3230`,达到"最大血量 × 一个受保护 float × 引擎常数"才请求一次(九项列表,优先级 3),且当前状态不能是 DOWN。推断(低):单次伤害占血量比例过大时的强制硬直。

**对 Unity 的含义**:
- `MonsterActor.ApplyHit` 现在的选择(倒地攻击且有倒地动画 → 倒地,否则交替受击一、二)与第 7、8 步一致;
- 已做(E-083,§18):倒地状态再挨打、高度大于 0 时直接倒地(第 6' 步),怪物有了 z;
- 已做(E-084,§19):已死怪物有倒地动作时走 DOWN(第 3 步),躺下的那一刻转入 DIE,白闪淡出后消失;
- 主角被怪物打中(E-086,§20):硬直与击退走同一套公式(受击方是主角);**第 1 到 8 步的决策顺序在 M16 对主角做了**(E-105,§21):`[damage reaction]` 为 none 只扣血,倒地类攻击、空中与倒地中被打、被打死的一击走倒地分支,其余走受击分支;
- 还没做:霸体与异常状态(第 2、4、5 步);第 1 步的"无反应"主角一侧已做(E-105,§21),怪物受害者一侧没做(眼下没有哪个主角攻击的 `[damage reaction]` 是 none);
- **倒地的击退与浮空会受怪物体重影响**(第 3 个参数的"受体重影响"位);公式在状态的"开始"处理里,见 §15、§17,Unity 实现见 §18。

**当时没找到、后来找到的**:DAMAGE、DOWN 状态"开始"之后的处理(硬直时长、击退速度曲线、倒地停留、体重缩放)在 `0x008360e0`(见 §15、§17)。客户端游戏类基本没有运行时类型信息(明文里只有标准库和界面类的几个名字),不能靠类名定位。

## 15. 受击状态的"开始"处理(E-080;静态读码)

**结论先说**:状态一旦被请求并开始,基类虚表 `+0x29c`(`0x008360e0`,参数是状态号和参数列表,按跳转表 `0x00838db8` 分到各状态的处理段)就把"硬直多久、往哪退多快"算出来。
受击(DAMAGE)的这一段读通了:**硬直时间有公式,默认击退与 `[push aside]` 无关**。倒地(DOWN)开始时的体重缩放与随机扰动也读出来了;倒地的每帧过程没读。

**跳转表**(观察):状态号 0 到 9 → `0x0083633f`、`0x00836618`、`0x008366e6`、`0x008367ac`(DAMAGE)、`0x00836c1a`(DOWN)、`0x00837612`(DIE)、`0x008377f1`、`0x008385b9`、`0x0083864c`、`0x00838877`。

**DAMAGE 请求列表各项怎么被用**(来源在第 13 节;按 1 起数):

| 项 | 内容 | 用处(观察) |
|----|------|-------------|
| 1 | 攻击方侧 | 经 `0x00766110(…, 4, 0)` 换成击退方向,交给槽 `+0x604` |
| 2 | 硬直倍率的百分数 | `int(100.0f × L)`,开始处理里 `× 0.01f` 再 `× 100.0f` 取整,算硬直的 `rate` |
| 3 | 受击动作序号 | 存 `this+0x32b8`,槽 `+0x480` 取受击动画 |
| 4 | 命中模式(`[hit info]` 第一个关键字) | 等于 2 时不击退 |
| 5 | 攻击方所属者的"受击恢复"属性 | 从受击方的同名属性里减掉 |
| 6 | `[force hit stun time]` | 非 0 时直接当作硬直 |
| 7、8 | `[knuck back]` 的类型与参数 | 类型 1、2、−1 改硬直与击退;类型 3 的参数交给 `0x008b05c0` |
| 9 | 仅在条件 `0x00706410`/`0x0075c4a0` 成立时读 | 存进 `this+0x322c`(请求的守卫字段) |

**硬直时间**(共用实现 `0x00833a20`,槽 `+0x698`;常数都是引擎代码里的立即数):

```
min、max、recmax = Etc/EtcParameter.etc 的 [hit delay time min]、[hit delay time max]、[hit recovery max]
                    (每个标签两个整数,按 0x00706410/0x0075c4a0 的条件选一个;条件没细读)
R   = 受击方"受击恢复"(属性组 3 的 +0x390 整数 × +0x39c 浮点,取整) + 怪物附加项(0x0084dae0,没读完) − 第 5 项
T   = int((min + max(0, (max − min) × (recmax − R) / max(recmax, 1))) × rate)      整数乘除向零取整
rate = (float)int((float)p × 0.01f × 100.0f) × 0.01f      p = 第 2 项 = int(100.0f × L)
L   = 攻击信息 +0x114 的浮点 [hit info] 浮点项(≈ −1 即没写 → 1.0)× ([attack type] == 1 ? 0.7 : 1)
[force hit stun time] ≠ 0 → T = 它;[knuck back] 类型 1、2 → T = int(rate × 333.0)
怪物(类型标志 0x211):T /= 0x00884360(k)(k 由 0x00925ff0 的 1..4 选 0..3;缺项或 0 当 1;推断:来自 .mob 的 [stun time balance])
```

读法:受击恢复越高,硬直越短;恢复到 `recmax` 以上就只剩 `min`;恢复为 0 时是 `max`。**命中延迟倍率**就是 E-077 里 `[hit info]` 的浮点项
(写 −1 时攻击方一侧用武器表补上),它在受击一侧乘进硬直。

**受击击退**(同一函数;v0 的单位是像素/秒、持续是毫秒):

| 条件 | v0 | 持续 |
|------|----|------|
| `[knuck back]` 类型 1 | 800 | `T` |
| `[knuck back]` 类型 2 | 400 | `T` |
| 命中模式 = 2 | 0 | 0 |
| `[knuck back]` 类型 −1 | 0 | 30 |
| 其余(包括没写) | 400 | 150 |

持续取 `min(持续, T)`(`[force hit stun time]` 生效时不取);减速度 = `v0 × (−1000) / 持续`(整数,向零取整;持续为 0 填 0);`this+0x3568` 的受保护整数为 0 时 v0 与减速度都填 0(不击退)。
所以**默认受击击退 = `v0 × 持续 / 2000` = 30 像素,150 毫秒内匀减速到停**;受击列表里没有 `[push aside]`,Unity 里那一项只该用在倒地。

**状态怎么结束**:DAMAGE 在每帧函数(`0x00835239` 一带)里按"状态已持续时间 ≥ `this+0x32bc`"结束(请求状态 0;异常状态 3 时请求 9)。计时器 `this+0x30a0` 是带暂停标志的秒表
(`0x011ba640`:暂停标志置位时返回存下的值,否则"累计 + 当前时刻 − 起点")。命中停顿有没有去暂停它没读到(推断,低:没有,硬直从被打中那一刻起算、包含停顿)。

**倒地(DOWN)开始**(`0x00836c1a` 起,观察):`this+0x3340` := 输出二,`this+0x334c` := 倒地类型;

- 类型 0(不受体重影响):水平量、`[lift up]` 用原值;
- 类型 1 到 3:先过体重缩放 `0x008327c0(a, 体重, 100)` = `a × 4000 / ((体重 × 100 / 100 − 10000) × 0.0121 + 2100.0)`(0.0121、2100.0、4000 是引擎常数)取整;
  浮空高度 `h = v² / (2 × |g|)`,`g` 取槽 `0x00833000` 的重力(默认 −1500,另有加减项没逐项读),再次倒地时 `h` 至少取 1;
- 弹起类(类型 2、3):先以 −400 的初始"高度"砸向地面,同时把 `[lift up]`(前一状态也是 DOWN 且 `this+0x3340` ≥ 2 时取一半)与 `[push aside]` 存进 `this+0x3354`、`this+0x3360` 供落地后弹起;
- 水平量取一半(有符号,`0x00837028` 一带);再各按均匀随机扰动:水平量 × [0.8, 1.2]、高度 × [0.9, 1.1](`0x011b98c0(a, b, 随机数 0 到 999, 999)` 是线性插值,与 `MonsterAbility` 里的插值同形);
- 状态 `0x10012`/`0x4fd1e` 的怪物高度归零;落地音按体重分三档(≤ 60000、≤ 100000、其余)。

**对照基线**(非 REA,本机计算):把本机 `.mob` 的受击恢复、`EtcParameter.etc` 的三项与主角武器的命中延迟倍率代入,算出的硬直落在基线连拍 S07 量到的 300 到 400 毫秒区间里;
"硬直包含停顿"与"停顿之后另算"两种读法算出的总时长都在区间里,基线分辨不出。数值不进仓库。

**还没找到**:怪物附加项 `0x0084dae0`、两值表的选择条件、`this+0x3568` 是什么、倒地水平量的单位(速度还是位移)与每帧过程(落地、弹起、躺地、起身与 `[stand up invincible time]`)、
DIE 开始(`0x00837612`)、其余状态(1、2、6 到 9)。

**对 Unity 的含义**:`MonsterActor` 的受击硬直换成公式(`[hit recovery]` 取 `MonsterAbility`,三张表运行时读用户自备的 `EtcParameter.etc`),
受击击退换成 v0 与持续的规则;倒地的停留与击退仍是占位。**已实现,见第 16 节(E-081)。**

## 17. 倒地(DOWN)的每帧过程(E-082;静态读码)

**结论先说**:倒地不是一个动作,而是**三个阶段**,靠"再请求一次 DOWN"串起来;躺多久由动画自己放完决定。
每帧函数 `0x00834760` 按状态号查跳转表 `0x008360b8`(九项),DOWN 的段从 `0x00835291` 到 `0x008359c4`。阶段号是 `this+0x3340` 的受保护整数(0、1、2),就是 E-079 里 DOWN 请求列表的第二项。

| 阶段 | 做什么 | 什么时候进下一阶段 |
|------|--------|--------------------|
| 0 腾空 | 记离地最高点(`this+0x3330`);撞墙时水平量变成 −值/5;z 速度 ≤ 0 时若动画停在第一个"停留帧"就换到下一帧 | 落地(权威端、z 速度 < 0、物体 `+0xd0` = 4):弹起类(类型 2、3)→ 再请求 DOWN [4, 0, 类型降一级, 存下的 `[push aside]`, 存下的 `[lift up]`];不弹起类(0、1)→ 再请求 DOWN [4, 1, 0, 水平量, 最高点 ÷ 5] |
| 1 颠一下 | 同阶段 0 的换帧;类型 0,颠起高度 = 最高点 ÷ 5(原值当高度用),水平量再减半 | 落地 → 再请求 DOWN [4, 2, 0, 0, 0] |
| 2 躺地 | 没有物理;开始处理把动画直接跳到记录帧 | 已死 → 请求 DIE [1];否则动画放完(或没有动画对象)→ "结束"(回状态 0,有待处理标志时回状态 1,异常状态 3 时回 9) |

- **提前结束**:`this+0x3224` 不是 −1 时,阶段 0、1 落地后(未死)直接"结束",跳过颠起与躺地;阶段 2 躺地时下一帧直接"结束"(起身)。时间戳由 `0x00832820` 存下,**只对主角启用**(使能字节只在主角角色类的初始化里置 1),装填发生在进入阶段 2 时,细节见 §19。
- **z 初速**:类型 1 到 3 的高度 `h = 缩放后的 [lift up]² ÷ (2|g|)`(整数除法),类型 0 的 `h` 是 `[lift up]` 原值(当高度);再 × [0.9, 1.1] 的随机数,由 `0x008b25c0` 换成初速 `v = √(2 × |g| × h)`,`g` 是物体的重力(怪物默认 −1500)。所以类型 1 到 3 的初速 ≈ 缩放后的 `[lift up]` × √(随机数);飞行时间 = 2v/|g|(推断)。体重缩放 `a × 4000 ÷ ((w × 100 ÷ k − 10000) × 0.0121 + 2100.0)` 对水平量与 `[lift up]` 各做一次(k = 100);类型 2、3 先存下 `[lift up]`/`[push aside]`、再把 `[lift up]` 换成 −400 去缩放(砸向地面);水平量之后除以 2、再 × [0.8, 1.2] 的随机数。
- **水平**:DOWN 开始时 `+0x5f0(0, V, V, 0, 0, 0)`,不给减速度(DAMAGE 给);摩擦 `+0x5fc(0, 0, 1000, 1000, 1.0f, 1.0f)`。推断(低):空中匀速、落地后按 1000 像素/秒² 滑停;摩擦的实现有一部分在受保护节里。
- **动画**:延时极长的"停留帧"由逻辑放行(最高点、落地);帧序号常数是各派生类初始化函数里的立即数,不在数据文件里;阶段 1、2 的开始处理把动画跳到记录帧。躺地时长 = 动画里最后一个停留帧之后各帧的延时之和。
- **已死的怪物**:E-079 说过,对象已死、没有在 DOWN/DIE 时,每帧函数会请求 DOWN [4, 0, 1, 400, 400](有倒地动作)或 DIE(没有);阶段 2 里已死标志为真就请求 DIE [1]。所以有倒地动作的怪物是"飞起来、落地、躺平,然后才死"。
- **权威端**:`0x007f9eb0` 为真才会切换状态(联机时只有对象的属主端);单机永远是权威端。
- **没读到**:物理积分与摩擦的缩放(受保护节)、各类帧序号常数(只看了一个类)、状态 1、2、6 到 9(DIE 的开始与每帧后来读了,见 §19)。

**对 Unity 的含义**(已在 E-083、§18 实现):`MonsterActor` 的倒地占位(固定停留、`[push aside]` 当总位移、没有高度)换成:z 抛物线(g = 1500,初速按上面的算)、水平匀速加落地摩擦、停留帧在"最高点/落地"放行、躺地按动画放完;
阶段 1 的颠起高度 = 最高点 ÷ 5;弹起类先砸地再飞第二次;有倒地动作的已死怪物躺完再死;怪物要有 z(受击框、精灵、头顶高度都带上)。

## 18. Unity 里的倒地(E-083;合成数值测试)

**结论先说**:怪物有了高度 z 和三阶段倒地:按体重缩放的击飞、z 抛物线、落地后颠一下、躺平、动画放完起身;空中与倒地中再挨打、弹起类砸地再飞、撞墙反弹、命中停顿冻结、空中被打死的落地都做了。纯数学在 `Dnf.Game.Knockdown`(`packages/com.dnfunity.game/Runtime/Damage/Knockdown.cs`),状态机在 `MonsterActor`(`packages/com.dnfunity.play/Runtime/MonsterActor.cs`)。

- **命中停顿**:冻结飞行位移与动画时钟(与 E-077 一致)。
- **普通受击也走倒地分支**:`[damage reaction]` 为 1 或 3 的攻击打中腾空(z > 0)或已在倒地中的怪物时(E-079 第 6' 步)走倒地分支,请求的阶段 = 已在 DOWN 且旧阶段 ≥ 1 且非弹起 ? 1 : 0;怪物转向攻击方,速度按请求重算,动画重放。

## 19. 死亡(DIE)与已死怪物的倒地(E-084;静态读码 + 基线逐帧 + Unity 实现 + 合成数值测试)

**结论先说**:原版的 DIE 状态本身几乎什么都不做——"每帧"过程是个空壳,"开始"处理只是换死亡动画、停掉附着效果、清速度。怪物"被打死到消失"的表现由两部分拼成:(1) **已死的怪物先走倒地流程**(腾空、颠一下,躺下的那一刻才转入 DIE;E-079 第 3 步加 E-082 阶段 2);(2) **白闪与淡出从血量归零那一刻就开始,和倒地流程同时进行**——基线连拍里被打死的怪物在倒地动画的后仰、腾空姿势上就是纯白的,不是落地之后才变白;从血量归零算起约 0.5 秒消失,倒地流程没走完也一样。白闪、淡出的读取方式、时长与"何时移除"没在代码里找到,Unity 里是照基线录像的粗略观察做的(推断,低置信度)。

**Unity 里的实现(E-084)**:
- `MonsterActor.ApplyHit`:血量归零时,怪物有倒地动作、调用方给了倒地输入 → 标记已死,用**这一击自己的** `[push aside]`、`[lift up]`、`[bounce]`、`[ignore weight]` 请求倒地阶段 0(E-079 第 3 步:已死且有倒地动作 → DOWN,列表是这一击的),流程照常(体重缩放、抖动、腾空、颠一下);阶段 2 开始时已死 → `EnterDie`(E-082):水平速度与 z 清零,进入 `MonsterPhase.Dying`。没有倒地动作或没给倒地输入 → 直接死亡(老行为不变)。
- 死亡时钟 `_deathMs` 从血量归零算起(命中停顿里不走):前 `MonsterTuning.DeathWhiteMs` 毫秒精灵是纯白剪影,之后线性淡出(整张精灵不透明度,Normal 混合),到 `MonsterTuning.DeathMs` 消失——无论这时是在倒地流程里(尸体还在空中)还是已经进入 DIE。没有抬升的一击一两步内进入 DIE;抬升大的一击(飞行比 `DeathMs` 长)尸体在空中就消失。
- 渲染:`SpriteFrame.Silhouette` 是同尺寸、RGB 全白、alpha 保留的缓存副本(缓存保证 Unity 按帧对象缓存的贴图不会反复生成);`MonsterSprites.SpriteAt` 新增 `silhouette` 与 `tintAlpha` 参数。房间清空仍等所有怪物进入 `Gone`,门洞在最后一只怪物消失之后才开。
- **测试**:`MonsterKnockdownTests` 改写 1 个、新增 5 个(无抬升的致命一击:白闪从血量归零开始、躺下、淡出、消失;短飞行的致命一击:飞完腾空与颠一下才进入死亡、死亡时钟从血量归零算;抬升大的致命一击:腾空的尸体是白的、在空中消失;没有倒地动作的怪物直接死;老签名死亡不变;死亡精灵是白色剪影、按帧缓存、不透明度随时间变化);macOS 离屏对拍加了四帧(第一只纯白还在飞、它淡出一半、第二只纯白、它淡出一半),CPU 与 Unity 逐字节零差异。
- **没做 / 没弄清**:死亡特效(碎片与血粒子、蓝色光环的光效动画)与 `.ptl` 粒子系统;`[die effect]` 的含义与消费者;`this+0x3370` 的动画名;移除的真实机制(没找到,Unity 用从血量归零算起的固定时长);掉落与结算的触发点;白闪与淡出的时长只有一次基线采样。

## 20. 怪物还手:出招打主角、主角受击与生命条(E-086;静态读码 + Unity 实现 + 合成数值测试 + 真实数据对拍)

**结论先说**:怪物不再只是靶子。它追到"这一招挥出去能打到主角"的位置就出招;出招动画里带攻击框(类型 15)的帧,与主角当前动作的受击框(类型 14)相交就算打中,**一次挥击最多打一下**;伤害交给原版公式(E-049);主角扣血、头顶飘红字、进受击硬直并被推开(硬直与击退走 E-080 的公式,受击方是主角、攻击方没有所属者);屏幕底部有生命条与魔法条(第一版是占位色块;E-088 换成了原版底栏,见 [hud.md](hud.md));血量归零主角停在受击姿势上、画面显示 DEAD、不再接受输入。
**靠近与出招的条件部分是推断**(出招决策的定时抽签、`[attack kind]` 记录与射程已读通,见 `docs/monster-ai.md`;基础攻击的触发与移动节奏没读通),**伤害公式的输入是推断**(客户端命中时怎么填那块结构没读通),**主角的生命、防御与受击恢复是占位**(只取 .chr 第一节的初始值,没有成长、等级与装备)。真实数据上跑通了整条链:怪物走过来、出招、打中、主角硬直、血条下降、红字上飘,自动机打完整座副本时主角存活。

**读到的(观察;静态读码,只记入口、偏移与调用关系,没有逐条追)**:

**推断**(都在 Unity 里实现了,**不要当成原版行为**):
- 没有 `[attack kind]` 的怪物(旧占位):出招用 `[attack motion]` 与 `[attack info]` 同下标的那一对(固定用第 0 个);出招间隔取 `[attack delay]`,没写取 1500 毫秒(这是我们自己的缺省值)。有 `[attack kind]` 的怪物按 E-100、E-101 决策:出生满 3 秒才开始、之后按 `[attack delay]` 加抖动抽签,挑第几招就放第几招的动画与攻击信息;射程全 0 的记录靠几何判断触发(Z1,推断)。
- 靠近到"出招动画任意一帧的攻击框与主角此刻的受击框相交(严格相交,位置向下取整)"就停下出招,最近停在离主角水平 8 像素之外(我们自己取的数);没有主角受击框、或出招动画没有攻击框时退回固定距离(旧行为)。有 `[attack kind]` 时(M14):某条可用记录够得着目标(射程范围,或第 0 招的上述几何判断)就停下,出招交给决策器按节奏决定。
- 一次出招只打一下,按"上次判到哪一帧"补判中间跳过的帧(与主角打怪物的补帧一致)。主角在空中时的受击见 §21(E-105)。
- 怪物投射物(M15,E-103):投射物的攻击框(类型 15)与主角受击框严格相交就算命中,命中后走与近战同一条伤害输入(`StrikeHero`:发射者的等级与攻击力,攻击信息取投射物 `.obj` 的 `[attack info]`),命中的投射物消失;飞行的速度、寿命与消失是推断(见 `docs/monster-projectile.md` §5)。
- 伤害输入(`MonsterDamage.Fill`):基础伤害 = 怪物的物理或魔法攻击力(看攻击信息的 `[attack type]`)× (100 + `[damage bonus]`) ÷ 100,公式里的"攻击力"项填 0(已经折进基础伤害);攻击者等级 = 怪物等级(防御率的分母用它,E-049);防御方的防御力取主角的 `[initial value]`;攻击者类型 `0x211`、防御方 `0x111`;怪物不暴击(假设)。

**读代码读出来的一个坑(观察,不是推断)——客户端的伤害输入默认值不是中性的**:初始化函数给的默认值,百分比加成是 1.0(直接用会变成 ×1.01)、额外倍率是 1.0(伤害翻倍)、最终百分比是 1(变成 ×0.01)、暴击属性是 1.0(暴击率 = 基础 3 + 加成 + 属性 − 抗性,会多出约 1% 的暴击)等等;这些项在命中时由客户端逐项填成真实的值。所以不能"新建一块结构就算",我们填的是"没有加成"的中性值,暴击率加成压成 −3、暴击属性填 0。一开始漏了暴击属性,合成测试在约 1% 的概率下偶发暴击才暴露出来。

**Unity 里的实现**:
- **怪物**:`MonsterActor.Think` 在"够得着"时进入出招阶段(`SwingNumber` 加一,`AttackEvalFrame`、`HitHeroThisSwing` 清零);`AttackBoxesAt(frame)` 取出招动画那一帧的攻击框(类型 15,跟着朝向镜像、跟着离地高度抬升)。`RoomCombatSession.ResolveMonsterHits` 每步对每个出招中的怪物补判帧,命中就 `StrikeHero`。
- **主角受击框**:`HeroHurtBoxes.At(hero)` = 主角当前动作的基础动画那一帧的类型 14 盒(世界坐标)。
- **`StrikeHero`**:伤害(读得到 `Etc/EtcParameter.etc` 的公式常量就走 `DamageFormula.Compute`,否则是"攻击力 × 加成"的占位)→ `HeroVitals.Damage`(返回这一下是否打死)→ 受击硬直与击退(`HitStun.Damage`,受击方恢复项取主角的 `[hit recovery]`,攻击方恢复项 0)→ `TownHero.BeginHurt`(放 `[damage motion 1]`、`[damage motion 2]` 交替;硬直计时不被命中停顿冻结;击退先快后慢 `1 − (1 − t)²`,被墙或通行带边缘挡住就停;会打断挥击与技能,挨打期间不能放技能;离地时不走受击硬直,改走倒地,见 §21)→ 命中停顿(攻击信息的 `[hit info]` 整数,怪物没有武器表)→ 红橙色伤害数字(位图字,位置取自相交盒,见 §22)。
- **主角死亡**:`Vitals.Hp` 归零 → `HeroDead`;会话不再读输入,怪物待机;主角有倒地动作时这一击把他打倒、躺下后不再起身(E-105,§21),没有倒地动作的脚本才退回"受击硬直变成永远"的占位;画面居中显示 DEAD。没有复活与结算。
- **占位 HUD**:屏幕左下角红色生命条与蓝色魔法条,上方各一行 "HP 当前/上限"、"MP 当前/上限"(`OverlayArt` 的占位字体与条,不是原版界面)。图包里找得到原版底栏时不再用它(E-088,[hud.md](hud.md));魔法的消耗与恢复在 E-087 做了(同一篇)。
- **`HeroVitals.FromChr`**:`.chr` 里第一次出现的 `[HP MAX]`、`[MP MAX]`、`[physical defense]`、`[magical defense]`、`[hit recovery]`(同名标签后面还有各成长类型的增量,只取第一次出现的初始值)。**在真实数据上第一次跑才发现**:这几项在真实 .chr 里存成浮点数,按整数读会当成"没写"、血量退成 1(合成夹具当初用的是整数,没能发现);现在一律按"第一个数值"读再四舍五入,测试覆盖两种存法。
- **换房间**:生命与魔法跟着人走(`HeroVitals.CopyStateFrom`,带的是当前值,不是回满);`DungeonSession.HeroHits` 是整座副本的合计。
- **无伤害模式**(命令行 `--no-damage`、播放器 `-dnfnodamage`、`tools/play-dungeon.sh nodamage`):主角没有生命值、怪物打不到他、不画血条,行为与怪物还手加入之前完全一致。按时刻比事件的回归检查(位置、命中、清房时刻、技能、死亡)都带它,否则还手会改变事件的时刻;怪物还手另有专门的检查。

## 21. 主角倒地与起身(E-105;静态读码补读 + Unity 实现 + 合成数值测试 + 真实数据核对)

**结论先说**:主角现在会像怪物一样被打倒。倒地类的攻击、腾空时被打、倒地中再被打、被打死的那一击,都让主角按 E-083 的三个阶段走:腾空 → 落地颠一下 → 躺着 → 起身;躺着以后累计受到的伤害超过最大血量的 15% 就提前起身(E-085,只对主角);被打死的主角倒下后躺着不动、不再起身。**怪物与主角共用同一个倒地状态机**:客户端的倒地(DOWN)状态函数是主动对象基类的实现,两边是同一批代码,所以 `MonsterActor` 里写好的整套逻辑被原样抽成 `KnockdownFlight`(与 `DownAnimation`),主角直接用。

**读到的(观察;静态读码与本机数据的只读核对,非 REA 工具)**:
- **基类共用**:倒地状态函数 `0x008360e0`、开始处理(E-083)、结束 `0x008337f0`、死亡 `0x00837612`、受击反应决策 `0x00822ca0`(虚表槽 `+0x504`)都是主动对象基类的实现,怪物与主角走同一批;体重是 `0x007692b0` 读出的合计体重。主角一侧已知的差别只有 E-085 的提前起身(只由主角职业类的初始化函数使能)。
- **倒地帧记录**:一个职业类的初始化函数 `0x00b869f0`(由 `0x00d16840` 调用;同一函数还读 `attack1 cancel`、`attack2 cancel`、`attack3 cancel` 三个标签)往 `this+0x32e8`、`+0x32f4`、`+0x3300`、`+0x330c`、`+0x3318` 五个记录里写 2、2、2、3、4;E-082 看过的怪物类只有前四项,第五项是躺地帧。这是引擎代码里的立即数,不在数据文件里。实现按动画结构推出同一组帧(最后一个长停留帧的下一帧 = 躺地帧;阶段 1 在最高点从第一个长停留帧换到第二个),与主角 `[down motion]` 指向的动画核对一致。
- **主角数据**:`.chr` 有 `[down motion]`、`[overturn motion]`、`[damage motion 1]`、`[damage motion 2]`、`[hit recovery]`、`[weight]`;倒地动画与怪物的同一种做法(带延时极长的停留帧,最高点与躺地由逻辑放行,加一帧躺着)。本机 PVF 的 `.chr`、`.mob`、`.skl`、`.atk`、`.ani`、`.equ` 里没有名字含 `invincible` 的标签,所以"起身无敌"没有数据来源(非 REA 的数据读取)。

**主角的受击反应(推断:把 E-079 的决策函数套到"没有霸体、没有异常状态"的主角上)**:

| 情形 | 结果 |
|------|------|
| 这一击的 `[damage reaction]` 为 none | 只扣血、飘字、放声音与命中停顿,主角不反应;若这一击把他打死,决策函数不产生反应,由每帧函数补发"推力 400、抬升 400"的倒地(引擎常数) |
| 把主角打死(有倒地动作) | 倒地照常走(腾空、颠一下),躺下的那一刻转入死亡,躺着不动、不再起身;不再被打 |
| 把主角打死(没有倒地动作) | 停在受击姿势上(占位的死亡,与之前一致) |
| 倒地类的攻击(`[damage reaction]` = 2) | 倒地分支 |
| 普通受击(1,或 3 按 1 处理)打中腾空(z > 0)的主角、或已在倒地里的主角 | 倒地分支;已在倒地里、已经落过地(阶段 ≥ 1)而且这一击不弹起,请求的是阶段 1(颠一下),否则阶段 0 |
| 其余(地面上的普通受击) | 受击分支:交替放 `[damage motion 1]`、`[damage motion 2]`,硬直与击退按 E-080 |
| 主角没有 `[down motion]` | 倒地分支退回受击分支(决策函数的"没有倒地动作就走受击") |
| z = 0 的跳跃蹲姿、落地硬直被普通受击打中 | 推断:不算腾空,被打断、回到地面受击(此前的实现是不受击) |

**Unity 里的实现**:
- `DownAnimation`、`KnockdownFlight`(`Dnf.Play`):倒地的运动与动画时钟——三个阶段靠"落地后再请求一次"串起来,z 抛物线(g = 1500,步内精确触地)、水平匀速、撞墙反弹 `−trunc(vx ÷ 5)`;长停留帧由逻辑放行(阶段 1 在最高点换帧、阶段 2 跳到躺地帧);躺着在动画放完(躺地帧本身是长停留帧时停 900 毫秒)后起身。两个宿主开关:`EarlyEnd`(只用于主角)与 `DieOnLying`(已死:躺下的那一刻转入死亡)。`MonsterActor` 改为委托给它,怪物原有的全部倒地测试零回归。
- `HeroKnockdown`(`Dnf.Play`):主角一侧的包装。请求倒地时打断主角正在做的事(挥击、技能、奔跑)、保持当前高度起飞;**E-085 提前起身**:进入阶段 2 时装填、累计量清零;装填之后每次受击累计伤害,累计 × 100 ÷ 最大血量 > 15.0 就触发;触发后落地时跳过颠一下与躺地、躺着时下一步起身;离开倒地状态或死亡时解除。已死的主角不受这条规则影响。
- `TownHero`(`Dnf.Render`):新增 `HeroMotion.Down` 与 `BeginDown`、`SetDownPose`、`EndDown`。Render 不引用 Game,所以倒地姿势(位置、高度、朝向、动画时钟)由 Play 一步一步交进来;倒地中忽略一切输入、不能放技能、不被 `BeginHurt` 与后退步打断;起身回到地面站立。受击框跟着倒地动画的当前帧与高度走(躺着时是躺着那一帧的框)。
- `RoomCombatSession.ReactHero`:实现上表;倒地飞行与命中停顿一起定住(用主角自己的步长推进);倒地期间与倒地结束不放跳跃落地声;死亡的主角倒下后 `ResolveMonsterHits` 与投射物命中都跳过。
- 命令行:`combat-check` 在被打中时打印倒地阶段与离地高度,状态变化行打印阶段,结尾行打印"主角倒地 N 次(起身 K 次,其中提前起身 M 次)";`tools/verify-all.sh` 的 flow 一项多了两个用例(一座首领房间里主角被打死后倒地躺平、一座有倒地类攻击的房间里主角活着被打倒又起身),共 7 个。

## 22. 伤害数字(E-107;静态读码 + 基线对照 + Unity 实现 + 合成数值测试)

命中处理在伤害结算之后调"生成伤害数字"(0x007f9610,cdecl `(所有者, x, y, z, 数值, 标志)`)。完整的机制、数字图、动画关键帧与位置公式见 `docs/damage-number.md`;和本文有关的接口只有三点:

- **位置取自相交盒**(§3,E-058):x = 盒中心 x + `rand % 20` − 10,z = 盒中心 z + `rand % 20` + 60,y = 受击者自己的 y;盒中心是 `(int)(尺寸 × 0.5f + 下界)`(单精度,向零取整)。所以会话里 `TryHit` 现在返回这一击的相交盒(`Aabb.Intersection`),`Strike` 与 `StrikeHero` 都带着它。
- **标志**:施加者是本机主角 → 位 0(黄色一套),受击者是本机主角 → 位 1(红橙色一套),暴击 → 位 4(还没有暴击);两个方向走同一段代码。
- **寿命**:数字从弹出到消失一共 1000 毫秒(暴击 1500),与命中停顿、受击硬直无关(数字有自己的时钟)。

测试:`AabbTests`(4 条)、`DamageNumberTests`(40 条)、`RoomCombatTests` 与 `MonsterAttackTests` 里关于数字位置、叠加层与寿命的断言;全套 1340 条通过(Data 92、Script 7、Squirrel 22、Game 420、Render 273、Play 526),0 警告。

## 23. 连击计数(E-108;静态读码 + 基线对照 + Unity 实现 + 合成数值测试)

每次命中,命中回调(0x008774e0,碰撞的 `onAttack`,施加者一侧)在"施加者的所有者是本机主角"时调界面信息窗口的登记函数 0x008ef980。完整的机制、画法、缓动公式与基线对照见 `docs/combo-counter.md`;和本文有关的接口只有三点:

- **计数**:窗口内每一击累计数加 1(`.atk` 的 `[stuck]` 偶发掷骰命中时不加,我们没有这个掷骰);累计数从 2 起显示;每次显示数更新就重启显示计时器,走满窗口后清零。窗口毫秒数在客户端是按职业查表的,表的装载处没找到,缺省 1200 毫秒取自基线标定(原占位是 2600)。
- **时钟**:窗口按界面时钟走(与命中停顿、受击硬直无关),所以停顿时连击不会被"冻住"。
- **命中点**:`TryHit` 成功之后、伤害结算的同一处调 `ComboCounter.Hit`,与累计命中数 `Hits` 同一个口径;怪物打主角不记连击。

测试:`ComboCounterTests`(20 条)、`RoomCombatTests` 里 2 条新测试(位图连击与窗口走满、占位文字),原有窗口断言的注释改成 1200 毫秒;全套 1362 条通过(Data 92、Script 7、Squirrel 22、Game 420、Render 273、Play 548),0 警告。

## 24. 主角打怪物的伤害输入(E-110;静态读码 + 服务端交叉 + 实现 + 合成数值测试)

命中结算(`TryHit` 成功之后)里,伤害由"伤害计算"槽(虚表 `+0x388`,0x0087b870)按攻击信息、攻击者面板与防御者面板填满伤害结构后交给公式(E-049)。字段对应、读属性槽的清单、额外命中规则、技能伤害的换算、面板的来源与没读通的部分见 `docs/damage-input.md`;和本文有关的接口只有四点:

- **接线**:`RoomCombatSession.Strike` 在命中时,**有主角攻击面板(`HeroPanel`)与公式常量**就调 `RollFormulaDamage`(`HeroStrikeInfo.Input` + 面板 + `MonsterActor.Defense`)算伤害,否则仍是占位伤害;结算顺序不变(先选目标血条,再 `ApplyHit`,再放声音与命中停顿,最后放数字)。
- **额外命中**:低于 50 级的怪物,攻击者与它上一次挨打时记下的不是同一个(`MonsterActor.LastAttackerId`)就乘 1.1;主角打中后写 `RoomCombatSession.HeroAttackerId`,所以同一个主角连续打,只有第一击算额外命中。
- **暴击**:公式返回是否暴击,伤害数字带暴击位(`DamageNumberFlags.Critical`,E-107)。
- **回归开关**:`--no-damage` / `-dnfnodamage` 不装配生命与公式常量,也就没有面板,主角打怪物仍是占位伤害,按时刻对拍的回归检查靠它保持原来的时刻。

测试:`HitDamageTests`(Game 33 条)、`HeroDamageTests`(Play 20 条);全套 1422 条通过(Data 92、Script 7、Squirrel 22、Game 453、Render 274、Play 574),0 警告。
