# 副本选择界面:世界地图(M9c,证据 E-094)

目标:把 M9b 里那张"深色底 + 像素字名单"的占位副本选择界面,换成原版的样子(基线 S05):整屏世界地图,每个副本一个入口标记和一张卡片,
选中的卡片大、带边框,其余的缩小;上下边有装饰条,底部有按键提示横幅、地图名的难度条和三个按钮;开场有"选择地图"横幅与卡片淡入。
所有图都读用户自备的图包,仓库里没有任何原版素材;布局由基线帧用 `dnf locate` / `dnf fit-sprite` 逐帧量出,整屏合成与基线对过。

## 1 数据链(观察)

界面是数据驱动的,没有写死副本:

| 文件 | 内容 | 用到的标签 |
|---|---|---|
| `worldmap/worldmap.lst` | 区域编号 → `.wdm` 文件 | (无标签,编号与路径成对) |
| `worldmap/*.wdm` | 一个区域(一张世界地图) | `[map image]`(底图图包名 + 帧号)、`[ui path]`(这个区域的界面脚本)、`[dungeon]`(副本编号与解锁条件成对,`-1` = 没有条件)、`[name]`(字符串键) |
| `worldmap/ui/*.ui` | 区域的界面控件 | `[ui controls]` 一行一个控件:`"[类型]" "名字" x y 可见 "图名" 参数…`,以 `[/ui controls]` 收尾;副本入口是 `[balloon]`,图名后面是"个数 + 值",最后一个值是副本编号、倒数第二个是气泡样式 |
| `dungeon/dungeon.lst` | 副本编号 → `.dgn` 路径(相对 `dungeon/`) | (无标签) |
| `dungeon/**/*.dgn` | 卡片相关的几项 | `[worldmap pattern info]`(组号、位置号、卡片图包名、帧号)、`[minimum required level]`、`[basis level]`、`[name]`、`[explain]` |
| `sprite/worldmap/selectdungeonslot/*.img` | 卡片的画 | 每个副本一帧 168×73,**副本名已经画在图里** |

全部 28 份区域界面脚本里共有 135 个 `[balloon]`,131 个用同一张 `selectdungeon02.img`(其余 4 个用别的图包),气泡样式号 0 到 17 共 18 种。
`[ui controls]` 的种类有 `[image]`、`[balloon]`、`[switchbox]`、`[text button]`、`[text]`、`[animation]`。
底部的横幅、难度条与按钮是所有区域共用的公共界面,位置在下面"画面"一节里直接量出,没有从脚本里逐项读。

**拼法**(`WorldMapCatalog`):`.wdm` 的 `[dungeon]` 里只留解锁条件为 `-1` 的副本;每个副本编号要在区域 `.ui` 里有对应的 `[balloon]`(给出标记位置与气泡样式),
在 `dungeon.lst` 里有路径(再去读 `.dgn` 取卡片的画与最低等级),三样都有才进界面。

## 2 画面(观察:位置与帧号是量出来的)

画布 800×600,所有精灵都在叠加层(`OverlayArt.UiRank`)里按下面的次序画;"控件原点"摆放时再加上各帧自带的偏移,和原版一致。
图包缩写:**UI** = `sprite/worldmap/selectdungeon02.img`,**WC** = `sprite/interface/windowcommon.img`,**PT** = `sprite/interface/newstyle/windows/party/party.img`。

| 次序 | 内容 | 图与帧 | 位置 |
|---|---|---|---|
| 1 | 世界地图底图 | `.wdm` 的 `[map image]`(800×600) | (0, 0) |
| 2 | 气泡(卡片背后的底板与尖角) | UI 30 + 样式号(样式 13 是 43,118×80) | 标记原点 + (−36, −77) |
| 3 | 入口标记(蓝色圆点) | UI 77(34×34,自带偏移 (1, 1)) | `[balloon]` 控件原点 |
| 4 | 没选中的卡片 | 卡片图 ×0.7(双线性),118×52 | 气泡原点 |
| 4 | 没选中卡片的徽章 | UI 106 ×0.7 | 气泡原点 + (100, −17) |
| 5 | 选中的卡片 | 卡片图 1:1,168×73 | 气泡原点 + (−27, −20) |
| 5 | 选中卡片的边框 | UI 0(174×79) | 气泡原点 + (−30, −23) |
| 5 | 选中卡片的徽章 | UI 106(35×39) | 气泡原点 + (120, −40) |
| 5 | 选中卡片上的等级文字 | 占位像素字 | 卡片画的左上角 + (6, 26) |
| 6 | 上下边装饰条 | UI 79(800×600,中间透明) | (0, 0) |
| 7 | 按键提示横幅 | UI 76(553×28,偏移 (86, 0)) | (200, 572) |
| 7 | "适当频道"横幅 | UI 64(553×28,偏移 (124, 0)) | (0, 572) |
| 8 | 地图名难度条 | UI 90(181×21,偏移 (13, 0)) | (604, 476) |
| 8 | 难度条上的小图标 | PT 23(15×15) | (745, 479) |
| 9 | 按钮:快速组队、返回城镇 | WC 66(97×23) | (700, 500)、(700, 541) |
| 9 | 按钮:深渊派对(灰) | WC 69(97×23) | (600, 541) |
| 10 | 开场横幅"选择地图" | UI 80(800×72) | (0, 250) |

标记、气泡、卡片和徽章在开场淡入之前不画;不透明度为 0 的精灵不进绘制列表。缩放后的卡片图与徽章按(帧对象, 比例)缓存,每一帧拿到的是同一个对象。

**缩放模型**(`SpriteScale.Bilinear`):目标像素 (x, y) 的源坐标 = ((x + 0.5) / 比例 − 0.5, (y + 0.5) / 比例 − 0.5),四邻双线性、四个通道各自线性插值(不预乘)、边缘夹住,目标尺寸取 `ceil(原 × 比例)`。
拿基线里没选中的那张卡片拟合,这个模型平均每通道误差约 2 到 3(满分 255),比最近邻、盒式和双三次都小;徽章缩放后与基线逐像素一致。

**文字**:卡片名、按键提示、开场横幅的字都画在图里;图里没有的(等级、三个按钮的文字、地图名)原版是中文系统字体,这里用自带的 5×7 像素字写英文占位
(`Lv. NNN~MMM` 这种写法,数字补零到三位、`QUICK PARTY`、`ABYSS PARTY`、`TOWN`、路径主干的大写当地图名),位置居中或对齐在原位置,大小是近似。字库为此加了 `~`。

## 3 时间线(推断:从界面动作脚本读出的时长,触发条件只理解了一部分)

- 开场 0 到 0.3 秒:"选择地图"横幅从透明淡入;0.3 到 1.0 秒停住;1.0 到 1.3 秒淡出。这段时间里标记与卡片是隐藏的。
- 1.3 秒起标记与卡片 0.3 秒淡入(之后一直是 255)。
- 底部两条横幅每 8 秒一个周期轮流出现:按键提示停 3 秒(255)、1 秒淡出、"适当频道"横幅停 3 秒、1 秒换回来;两条横幅的不透明度之和恒为 255。开场先是按键提示。
- 界面自己的时钟由宿主推进(`DungeonSelectScreen.Advance`;`Build` 的墙钟参数不用),所以动画从界面打开那一刻开始算,CPU 与播放器按同样的步长得到同样的画面。

## 4 交互

- ↑ ↓:按标记在地图上的位置从上到下换选中的副本(同一高度从左到右),到头不循环;←→(选难度)没做。
- 回车或空格:进选中的副本。Esc:回城镇。
- 鼠标(触摸):点没选中的卡片选中它,再点选中的卡片进入;点"返回城镇"回去;点"快速组队"与"深渊派对"没有反应(单机没有组队)。
- 自动机(`FlowBot`)在界面停 2.5 秒再确认,比开场动画(1.6 秒)长,所以检查画面时卡片已经出来了。

## 5 代码

- `Dnf.Render.WorldMapDef`:`.wdm`;`UiScript`/`UiControl`:`.ui`;`DungeonCardDef`:`.dgn` 里卡片相关的标签;`SpriteScale`/`ScaledSpriteCache`:缩放与缓存。
- `Dnf.Play.WorldMapCatalog`:把上面几样拼成条目(`DungeonEntry` 带 `DungeonCard`)与画面数据(`WorldMapScene`)。`Build` 是纯逻辑,合成数据可以直接测。
- `Dnf.Play.WorldMapArt`:画法(位置常量、时间线、点击测试、按图包缓存的实例)。取不到的帧就不画;卡片没有画时画占位块和副本名。
- `Dnf.Play.DungeonSelectScreen`:有 `WorldMapScene` 时画世界地图,没有时还是 M9b 的占位名单;逻辑(移动、确认、返回、结果只认第一次)两种模式一样。
- `GameFlow` 构造时可以带 `WorldMapScene`;播放器 `-dnfworldmap <PVF 路径|none>`(默认洛兰)、命令行 `flow-check --worldmap <路径|none>`。

## 6 验证

- 合成数据单元测试 34 条:Render 12(`WorldMapDefTests`:`.wdm`/`.ui`/`.dgn` 的读法、列表解析、缩放的精确值、缓存)、Play 22(`WorldMapTests`:时间线边界、点击与矩形、绘制次序与每个精灵的位置/不透明度、缺帧占位、导航次序、点击流程、目录的筛选、流程与自动机)。
  全套测试 1033 条通过(Squirrel 22、Script 7、Data 92、Game 369、Render 248、Play 295)。
- 命令行 `flow-check --from select --shots-at 0.4,1.0,1.5,2.0,2.4`(真实数据)按时刻出图;2.0 秒那一帧与基线 S05 对比:排除聊天窗口与各处文字之后约 3.6% 的像素有差别(重采样噪声与卡片边缘),
  与我自己用 Python 合成的参考(同一模型)只差 0.15%(没画的第二个徽章)。
- Unity EditMode 44 条(34 通过、10 条要显卡的跳过、0 失败)。
- macOS 播放器离屏渲染 0.7 与 2.0 秒两个时刻,与 CPU 合成逐字节一致,全部 37 帧对拍零差异(此前 36 帧,占位选择界面那一帧换成这两帧)。两个时刻选在不透明度恒定的区间(横幅停留中、卡片全部出现、按键提示横幅还没开始换),不在淡入淡出的边界上:CPU 的 `--shots-at 0` 实际是第一步之后的 16 毫秒,开场横幅已经亮起一点,与播放器精确的 0 毫秒差几个灰度(第一次对拍的 0 秒帧就是这样不过的),不是渲染差异。
- 播放器实时(无人值守、时间 ×4)走完整条流程:七次阶段切换、三局、墙钟 27.5 秒、声音读失败 0。

## 7 推断、占位与没做

- **中文文字**:等级、按钮文字、地图名是英文像素字占位;原版是系统字体。统一的文字系统(中文字体)留到后面的"文本系统"里再做。
- **气泡样式**:18 种样式里只量过样式 13(位置、卡片在气泡里的偏移);别的样式换上对应的气泡图,位置按样式 13 的几何画,不一定对得上。洛兰一个区域够用,别的区域上线前要补量。
- **徽章**:选中与没选中的卡片右上角都有一个小徽章(UI 106),含义没确认,所以每张卡片都画一个;有的卡片上还有第二个徽章(UI 107)和一小段"活动"字样,没画。
- **等级区间**:只有一个基线样本,"下限 = 最低等级、上限 = 下限 + 1"是照这个样本猜的,低置信度。
- **导航次序**:原版的上下键怎么在卡片间走没读到客户端代码,这里按位置排;再点一下确认也是占位的交互。
- **解锁条件**:`[dungeon]` 里不是 `-1` 的副本(推断是要先做任务)先不显示;条件的含义没读。
- **开场动画的触发**:时长读自界面动作脚本,触发的语义只理解了一部分;没做卡片弹出时的缩放动画和悬停高亮。
- **难度**:←→ 选难度、难度条上的内容、小图标的含义都没做(图标是 PT 23,按原样画)。
- 只有洛兰这一个区域在检查里验证过;别的区域的 `.ui` 能用同样的方式读,但画面没有逐一核对。
