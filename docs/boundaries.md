# 范围与边界

这个项目是**重新实现**:用原创代码读取用户自备的数据,在 Unity 里复现游戏的运行规则。思路类似 OpenMW 之于 Morrowind。

## 硬边界

1. **只含原创代码。** 仓库里不放任何从 `NPK`、`PVF` 解出的素材与脚本,也不放反编译出来的原版代码、汇编清单、反编译器的自动命名结果。
   - 机械保障:`.gitignore` 排除 `re/`、`out/`、`local.env` 与原版扩展名;`tools/guard/precommit.py` 在提交前再检查一遍(路径、扩展名、大小、容器魔数、反编译器输出特征、凭据取值及其编码写法、本机绝对路径、私钥与令牌);
     发布到公开仓库前,`tools/publish-github.sh` 还会把同一套规则对每个分支与标签的整段历史再过一遍(见 [使用手册](usage.md))。
   - 数据由用户自备,运行时从用户指定的目录读取,按需解码,不落盘到仓库。
2. **不绕过官方服务的反作弊,不做外挂或修改器。** 网络协议只在用户自己的服务器上抓包与验证。
3. **保护层:用户已授权逆向(2026-10-15)。** `DNF.exe` 的保护层(`TerSafe`、名为 `nsn` 的节、`.rsrc` 里的 `FILE` 与 `HSH` 资源)原先要求"动之前先问"。用户在 2026-10-15 的答复是"给你最高权限 你想逆向就逆向"(原话;针对"黑盒区域怎么处理"与"是否批准在模拟器里运行客户端里的函数"两个提问,并附带追问"能逆向吗")。据此允许:静态分析受保护区域、在 CPU 模拟器(不是游戏本体)里运行客户端与服务端的机器码并跟踪、离线还原被混淆的代码。
   **这条授权的边界**:仍然不分发、不提交原版内容与反编译代码;不连官方服务、不绕过官方服务的反作弊、不做外挂或修改器;不碰凭据与服务器私钥;不改用户现有的游戏目录。运行游戏进程做运行时转储或附加调试器,先用静态与模拟的办法,实在不行再做,动手前在台账里写明方法与范围。
4. **不暴露凭据。** 不读取、不记录、不提交启动器配置里的密钥(如 `Config.toml` 的 `aes_key`)。
5. **不改用户现有环境。** 未经要求不修改原游戏目录与 DNF-CX 启动脚本;不运行游戏,除非用户明确同意;CrossOver 试用期重置相关内容不参与任何新工作。

## 证据纪律

- 每条被实现的规则都要能追溯到一条**证据**或一次**差分测试**(同样输入在原版客户端与 Unity 里各跑一遍再比较)。
- 结论要区分**观察**、**推断**、**未知**。静态分析不能说成观察到了运行。
- 普通 shell 或 Python 的测量不是 REA 证据,台账里单独标注。
- 台账见 [evidence/ledger.md](evidence/ledger.md)(卷首有分卷索引,E-300 以前在两卷冻结归档里)。
