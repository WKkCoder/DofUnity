# 移动端:触屏操作层与数据目录(M13)

目标:让 Android / iOS 上能玩——手指要能走位、奔跑、攻击、跳跃、放技能、暂停,数据要能放进手机。
**这一层是本项目自己的设计,不是对原版的还原**:原版客户端是键盘游戏,没有触屏界面,所以这里没有证据编号可引。
它只做一件事:把手指的按下、移动、抬起翻译成键盘路径本来就吃的那一组输入(方向 -1/0/1、刚按下的攻击/跳跃/技能键),
主角、战斗、技能的规则一行不改,触屏与键盘走同一条路。

## 1 摆法

- 代码:`Dnf.Play.TouchLayout`(摆法)、`TouchControls`(状态机)、`TouchScript`(按时间表替手指操作的测试工具)——纯逻辑,不依赖 Unity,有单元测试;
  `Dnf.Client.TouchOverlay`(Unity 一侧:读 `Input` 里的触摸、画控件)接在播放器 `TownDemo` 上。
- 控件摆在**屏幕**上(贴着安全区的边),不摆在 800×600 的画面里:宽屏手机上画面两侧的黑边正好放手指。尺寸都按屏幕短边的 1% 缩放,手机、平板、桌面窗口里比例一样。
  - 左下:浮动摇杆区(宽度取安全区宽的 40% 与 48 个单位里大的那个,从安全区高的 30% 往下)。静止时画一个底圈与拇指;手指在区里按下的那一点就是原点。
  - 右下:**ATK**(普通攻击,键盘 X)在最下;**JMP**(跳跃,C)在它左边;**A S D** 三个技能键在它上方的一段弧上(就是键盘路径里的 A、S、D 三个技能快捷键,E-076)。
  - 右上:暂停/继续(键盘空格)。
  - 单元测试里 8 种屏幕尺寸(4:3 到 21:9、带与不带刘海边距)逐一检查:每个控件整个圆都在安全区里、任意两个控件至少隔 0.4 个单位、按钮放大后的判定圈不压到摇杆区、静止的摇杆整个在屏幕上。
- 画面:桌面上仍然是整数倍放大(与原版像素一一对应);手机、平板与开着触屏操作层时改成**填满安全区的高度**(倍数不是整数,像素略有不均)。
  整数倍会让 800×600 只占一块 1080p 手机屏幕高度的一半多一点。控件会盖住画面的左右下角一部分(和多数手机动作游戏一样,控件是半透明的)。
- 只在带主角的场景里出现(城镇、副本),选角、副本选择、加载画面、结算菜单里不出现(那些界面本来就能点:触摸被 Unity 模拟成鼠标点击,走原来的点击路径)。
  开着触屏操作层时,点画面其它地方不再暂停(原先"点一下暂停"是给没有空格键的触摸屏准备的),暂停用右上角的按钮。

## 2 手势怎样变成输入

| 手势 | 输入 | 参数 |
|---|---|---|
| 在摇杆区按下并拖动 | 方向(八向,斜着走时水平与竖直同时有输入;向上是 dirY = -1,与键盘路径一致) | 死区 0.30 倍半径;某个轴"进入"阈值 0.42、"退出"阈值 0.32(单位向量分量;滞回,手指压在扇区边界上不会来回跳);水平与竖直各约 50° 的扇区,斜向约 40° |
| 拖得很远 | 原点跟着手指走 | 超过 1.5 倍半径就追,所以反向时不用拖回很远 |
| 把摇杆推到最外圈 | **奔跑** | 进入 ≥ 1.00 倍半径,退出 < 0.80 倍半径(滞回) |
| 按下 ATK / JMP / A / S / D | 刚按下的边沿(按住不连发,每次按下只给一次) | 判定半径比画出来的大 25% |
| 按下暂停 | 暂停/继续(宿主在暂停时也读它) | |
| 不在任何控件上的按下 | 不认领 | 宿主可以拿去做别的 |

多点触摸:摇杆与每个按钮各认各的手指编号,可以一只手拖摇杆、另一只手同时按多个按钮;抬起与取消(系统打断)都会正确松开。屏幕尺寸或安全区变了就重新摆放并松开所有手指。

**奔跑的翻译**:原版的奔跑只认"双击方向键"(同一水平方向按下、松开、再按下,两次按下的间隔不超过 300 毫秒,站立或行走时、角色有奔跑动作才生效,读自客户端代码,E-073;`TownHero.TrackTap` 是我们的实现),触屏上没有"双击摇杆"这个自然的手势,
所以把"推到最外圈"翻译成一次双击:手指进入外圈时,在接下来几帧的输出里插进"松开、按下"的序列——站着时是 `按、松、按`,已经在走时是 `松、按、松、按`——
让 `TownHero` 看到的恰好是一次间隔很短的双击;之后保持方向就一直奔跑;退回内圈时输出一帧"方向全空",奔跑结束、接着走路。
在奔跑区里换到相反的水平方向会再放一次序列(向另一边奔跑)。奔跑是否真的开始仍由原版的逻辑决定(角色没有奔跑动作、正在挥击或跳跃时序列白放,没有副作用)。
单元测试用合成的主角核对:推到外圈时水平方向输出依次是 `1,0,1,1,…`(站着)与 `0,1,0,1,…`(已在走),序列放完后主角进入奔跑状态;奔跑的稳态速度与键盘双击的完全相同;
退回内圈后主角先站一帧再走路;反向时向另一边奔跑;序列放到一半手指抬起则作废;摇杆走路时主角的位置与按住方向键逐值相同。

## 3 验证

- 单元测试 26 条(`src/Dnf.Play.Tests/TouchControlsTests.cs`):摆法(8 种屏幕)、八向与死区与滞回、原点跟随、按钮边沿与多指、不被认领的触摸、判定宽容度、暂停、换尺寸、奔跑序列(上面的各种情形)、
  触屏时间表与键盘时间表在 360 帧里逐帧给出同一组输入、时间表在 3 种分辨率下行为一致、时间表的格式错误与乱序。
- 播放器(macOS,`tools/unity-build-town.sh macos`,`-batchmode` 无窗口):`-dnftouchscript` 走真实的触屏路径(时间表 → `TouchControls` → 与键盘同一组输入 → 会话)。
  城镇里"摇杆向左推到外圈、3 秒抬起"与键盘 `-dnfautowalk 0.5:left,3:none` 停在同一个位置(可走区域左边界、朝左、站立、镜头 0);
  房间里把键盘技能时间表逐项换成 `stick`/`tap`:A、S、D 各放出一次且命中过怪物(脚本检查的就是这两条);手工对过日志,命中与击杀的计数与键盘那一遍相同。
  终点位置不拿来比:实时运行的帧间隔有抖动,键盘时间表连跑三次主角的终点也会有出入(后跳在哪一帧落地不同,最多差十几像素),严格的等价由单元测试里的逐帧输入比对负责。
- 屏幕上的样子:带窗口跑一次 `-dnftouchshot` 把整个窗口(含控件)存成 PNG,检查摆法(16:9 与 2.2:1 各看了一张,控件都在屏幕里、不重叠、按钮亮起与奔跑区变橙都对)。
  这会弹出一个短暂的窗口,所以没有放进无人值守脚本;命令见下。

```
DnfTownDemo -dnfdir <数据目录> -dnfmap map/lorien/s2.map -dnfnodamage -dnfnosound -dnfnohud \
  -screen-fullscreen 0 -screen-width 1440 -screen-height 664 \
  -dnftouchscript "0.3:stick=right+run,1.5:hold=attack" -dnftouchshot out/touch-overlay.png -dnftouchshotat 2.5 -dnfquitafter 4
```

## 4 桌面上试触屏

- `-dnftouch`:开触屏操作层,鼠标左键模拟**一根**手指(只能试单指操作:拖摇杆走位、点一个按钮;多指同时操作只有单元测试覆盖)。键盘照常可用,两者合并(方向以键盘为先)。
- `-dnftouchscript "秒:动作,…"`:按时间表替手指操作(`stick=right`、`stick=left+up`、`stick=right+run`、`stick=none`、`tap=attack|jump|a|s|d|pause`、`hold=…`、`release=…`),不读真实的触摸与鼠标。
- `-dnftouchshot <png> [-dnftouchshotat <秒>]`:实时运行到那一刻把整个窗口存成 PNG。`-dnfnohud` 去掉左上角的调试文字(手机上默认就没有)。

## 5 数据目录(手机)

原版数据不随应用分发,要用户自己放进去。播放器按下面的顺序找数据目录(`TownDemo` 的头注释有完整说明),手机上用的是最后一条:
**应用的持久数据目录下的 `DNF` 文件夹**(`Application.persistentDataPath/DNF`),里面要有 `Script.pvf`、`ImagePacks2/`;声音还需要 `audio.xml`、`SoundPacks/`、`Music/`(没有声音数据时安静地没有声音)。

- Android:包名 `com.dnfunity.client`,目录是 `/storage/emulated/0/Android/data/com.dnfunity.client/files/DNF/`。应用装好、运行过一次之后,用 `adb push <本机的数据目录>/. /sdcard/Android/data/com.dnfunity.client/files/DNF/`
  放进去(Android 11 以后文件管理器看不到 `Android/data`,用 adb)。找不到数据时界面会显示一个路径输入框,但手机上输入路径很不方便,建议直接用上面的位置。
- iOS:目录是应用沙盒的 `Documents/DNF/`。要让用户能从"文件"应用或 Finder 往里拷,还需要在构建出的 Xcode 工程 `Info.plist` 里打开 `UIFileSharingEnabled` 与 `LSSupportsOpeningDocumentsInPlace`。
  **这一步现在还没做**:本机没有 iOS 模块与完整 Xcode,构建脚本没有 iOS 目标;有了环境之后要补一个构建后处理(写 `Info.plist`)。
- 两个平台第一次进入时屏幕上会显示 "Could not find the game data folder" 与路径输入框,这就是数据没放对的信号。

## 6 没做、没验证的

- **没有在真机或模拟器上跑过**:触摸读取(`Input.GetTouch`)、安全区(`Screen.safeArea`)、手机上的画面填充都只有桌面上的模拟与代码审查,Android 构建能通过(IL2CPP,0 错误),但没有运行过。手感参数(死区、扇区、外圈、判定放大)是按常见做法定的,没有真人调过。
- 技能键上没有原版的技能图标与冷却显示,按钮上是 `ATK`、`JMP`、`A`、`S`、`D` 的英文字母(默认字体没有中文字形;游戏画面里的原版 HUD 仍在画面里,按钮盖住了它的一部分)。
- 摆法不能自定义,也没有设置界面;摇杆"推到最外圈"这个手势本身是我们的约定,原版没有对应物。
- 选角、副本选择与结算菜单靠触摸被 Unity 模拟成鼠标来点,没有专门为手指放大点击区域;选角界面的"方向键移动选中"没有触屏等价物(能点格子)。
- 没有手柄支持。
