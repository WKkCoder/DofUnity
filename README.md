# DofUnity — DNF 的 Unity 实现

逆向《地下城与勇士》(DNF)客户端,再用 **Unity 6** 以原创代码把规则一条条重新实现出来。
运行时只读取**你自己持有的**原版数据(`Script.pvf`、`ImagePacks2/`);**本仓库不包含、不分发任何原版内容**——
素材、脚本、反编译代码一律不入库,由提交守卫机械把关(见[原则与边界](#原则与边界))。

- **目标**:Windows / macOS / Android / iOS 四个平台,用自备数据跑通「登录 → 选角 → 进城 → 进副本 → 击杀 → 结算」。
- **现状**(2026-11-27):**单机**整条流程已能在 macOS 上从选角玩到结算,成长与装备周边的系统(疲劳、觉醒、强化、制作、称号、仓库等)也陆续落地;
  **联网**(只对作者自己的服务器)已能登录、选角、进城、保持连接,在真服上走完「进副本」五步、拿到起始地图,城镇快照里的等级与职业也已从加密信封的内层读出;Unity 宿主带 `-dnfonline` 有中文登录、选角(含默认关闭的建角/删角面板,E-459)、选服务器与选频道(`-dnfserverui`)、联网城镇(已接入内存物品/装备/金币实时同步,零写存档,E-458)、世界地图选副本进图与放弃回城(E-440)、结算页与结算后菜单(含主角输入冻结,E-449、E-456);更已建成真实加密/真实 TCP 本地回环假服务端(`src/Dnf.NetFake`)与无人值守驱动(`-dnfonlineauto*`),经 `tools/online-e2e-mac.sh --dry` 在真实 Unity macOS 播放器上跑通 9 阶段 + 重试闭环(E-461,未连真服);
  **进副本之后的战斗联网**(房间摆怪、击杀上报、结算回城、默认关的联网房间自动机与探针 `fight --after-settle` / `--min-clear-seconds`)代码已落地,**击杀命令已被真服接受(起始房 4 条全部确认),放弃回城也已在真服验过(返回城镇的推送序列与此前读码不同,联网层判据已据此修正,E-476、E-479);清图通知、结算、换房与物品流的真服回包还没验证**([详见](#联网p7做到哪下一步做什么))。
- **命名**:代码里是 `DnfUnity`、`Dnf.*`、`com.dnfunity.*`;文档与注释用中文。
- **许可**:尚未选择,见[版权与许可](#版权与许可)。
- **发布**:公开仓库 [WKkCoder/DofUnity](https://github.com/WKkCoder/DofUnity);全部分支与标签都先经审计、脱敏,再用 `tools/publish-github.sh` 发布,发布与审计记录见 [docs/usage.md](docs/usage.md)。

## 联网(P7)做到哪、下一步做什么

**已经通的**(都在作者自己搭的服务器上实测,证据 E-357 至 E-387、E-402):
网关握手(AES-256-GCM)→ 帧层 → 14 个会话密码槽(与服务端原函数逐位一致)→ 真实登录 → 逐槽选角 → 进城包流 →
心跳保活 → 「开始游戏 → 装载通知 → 选副本 → 副本信息 → 起始地图」。Unity 开发版宿主带 `-dnfnet` 启动时,会先在后台把「网关登录 → 取游戏服地址 →
连频道 → 游戏登录 → 逐槽选角」整条链跑完再进入城镇;再带 `-dnfnetdungeon <副本编号> <模式 0–4>`,进城后会在同一条会话上接着走完进副本五步,然后接上心跳;进图后宿主还会在房间里摆出本地怪、接上联网战斗(见下);不带它、只带 `-dnfonline` 时,在联网城镇的世界地图上选副本进图走的是同一套五步,另配许可灰显、提示条与放弃回城(E-440);再带 `-dnfbot` 与 `-dnfnetbot`(默认关)时,联网房间里改由自动机打怪。
凭据只从本机未入库的配置文件读取(探针与宿主的用法见 [docs/usage.md](docs/usage.md))。

**曾经的卡点「561 号信封」已经解开(E-386)。** 服务端对标记为需要保护的包,统一改发编号 561 的加密信封:
角色列表与选角回包、进副本时的「开始 / 副本信息 / 起始地图」三个通知,以及(很可能)角色本体数据,都在信封里。
信封原本由客户端的反作弊/保护模块解开,那部分代码磁盘上是空的、运行期才展开,静态读码到此为止(E-374)。
后来的做法是**在 CPU 模拟器里运行原函数**(不运行游戏本体、不连官方服务,在[边界文档](docs/boundaries.md)第 3 条的授权范围内),
拿仿真结果当裁判,再把 19 个密码块核、密钥派生与完整性校验逐个用 C# 写出来:全部与裁判向量逐字节一致;
作者本机保存的 33 个真实信封,用 C# 实现解开的明文与原函数仿真的明文**逐字节一致(33 比 33)**。

**真服验证(E-387)**:进城后在同一条会话上依次完成开始游戏、等装载通知、选副本、等副本信息、等起始地图五步,
三个通知都由信封解开(实测信封全开、零未拆),宿主进副本完成、心跳正常接上。

**内层帧的解压也在真服生效(E-390、E-402)**:信封拆开后的内层帧若属于压缩包号集合,会话层现在先认 zlib 头、再用与外层同口径的严格解压器解开
(头认不出的不碰,认得出却解不开的原样交出并计数)。真服复验里,城镇快照的等级、职业、成长类型从占位符变成了数字,与所选槽里的角色对得上,收到的信封全数解开、零未拆。

**进副本之后的战斗联网:代码已落地,击杀命令真服已验、结算真服未验(E-392、E-403、E-417)**。网络层有一台状态机:起始地图的怪记录按到达顺序给本地编号,对外只认每条记录里的服务端编号;
本地怪死亡时按服务端编号发死亡命令,清图通知到达后才发结算命令,通关结果与通关奖励两段通知收齐才允许回城,每一步都有门控(报过的、不在表里的、结算已发的一律拦下、不发包)。
宿主按起始地图的怪物记录在房间里摆出同数目、同顺序的本地怪,本地击杀经状态机上报,两段结算收齐后自动回城。这一套有完整的假会话测试和变异检查;
2026-11-13 的真服运行里,起始房 4 条击杀全被确认(E-417);清图通知与结算回包仍未亲见。

**第一次真服击杀:被接受(E-416、E-417)**:联网探针新增 `fight` 子命令,不开 Unity 就能无头走完「进城 → 进副本 → 对起始地图的怪逐只发击杀 → 等清图通知 → 等结算」,只打脱敏的行,认证失败立即退出、绝不重试。2026-11-13 的一次真服运行(一次登录)里,一个起始房有 4 只怪的多房间副本的 4 条击杀全被服务端确认、零拒绝——联网层缺省击杀载荷被真服接受;起始房杀光后 25 秒没有清图通知,与「多房间副本只在最后一间发清图通知」的推断相符(推断,没有对照实验)。**清图通知与结算两段的真服回包仍未见,单房间副本与换房的真服运行都还没做。**

**清图之后的结算对话读清了(E-414、E-415,纯读码,真服没见过这几种帧)**:清图通知没有载荷、客户端在常规分支里一收到就自己发结算命令(33 加 6k 字节;另有一个不发的分支没读通);通关结果(9 加 7n 字节)里的评分档位来自客户端那条命令第 1 个字节的回显,不是服务端写的评分值;通关奖励(89 加 15n 加奖励信息额外字节)的客户端读序是虚拟化桩,读不出,字段边界以服务端写序为准。联网层有了三个只读解析器;其结果后来作为只读附件挂在战斗状态机的事件与结果上(E-431),结算页读的就是它(E-449),状态机放行仍只按通知包号、不看解析成败。

**联网会话拆成了阶段(E-419,只到联网层)**:原来「一口气进城」的编排现在由一个分阶段会话承担——登录、连频道、选角、换频道、断开、心跳开关与进副本前的独占收包各是一步,顺序错误抛异常,断线用事件报告(对端关闭、读错、写错、本地空闲超时);进城编排改为组合这些阶段,出站帧与以前逐字节一致。换频道现在是「关旧连接、用同一网关令牌连新频道、重新登录游戏服」,**服务端是否要先收到退出命令没有真服验证**;本地空闲超时是客户端自己的监督策略。宿主层还没用它,联网界面几条线以它为底。

## 还没做、还没验证的

诚实列出,免得被「完成」二字误导:

- **联网**:见上节——清图通知与结算的真服回包、多房间副本的联网战斗(联网层与宿主层都有了、只经假服务端验证,E-408、E-428,真服没换过房)、角色本体数据、心跳校验值。只在作者自己的服务器上验证过。
- **平台**:只有 macOS 完整跑过。Windows(Mono)与 Android(IL2CPP)播放器最近一次构建通过是在 2026-10-21 前后(见路线图 P8a),
  此后各轮改动都没有再构建,也从未运行;iOS 缺完整 Xcode,没构建;触屏层没在真机上验证。
  开发机现状(2026-11-27 查):没有 Windows 机器;iOS 只有命令行工具、没有完整 Xcode 与 `simctl`,起不了模拟器;Android 有 SDK 与模拟器程序,但没有系统镜像、没有虚拟设备、没有命令行工具包(`avdmanager`、`sdkmanager`),也没连真机——这三个平台目前都没法在本机验证运行。
  macOS 播放器与编辑器测试最近一次复验是在 2026-11-27(R21 三线合并与文档批之后的主干,E-482;此前 2026-11-26 R20 八线合流之后的复验见 E-461、E-462):编辑器测试 82 项通过 72、失败 0、跳过 10(跳过的是需要显卡的渲染测试),
  桌面正式构建后 69 次离线运行退出码全为 0(15 趟时间放大运行与独立副本探索均已改由 `-dnfquitaftersim` 游戏时钟收敛,262 行通过判据未变,E-457);开发构建(`macos-dev`)另通过 `tools/online-e2e-mac.sh --dry` 本地回环端到端实跑(9 阶段 + 重试闭环,退出码 0,E-461)。
- **人手与人耳**:键盘手感、声音对不对,没有人逐项验证过;自动化对拍只覆盖画面与逻辑。
- **推断与自己的设计**:部分数值与规则是推断或占位,界面里的中文措辞与窗口版式是自己写的、没有对过原版,
  `docs/*.md` 里的「推断」「非 REA」标注和证据台账的「置信度」列逐条写明。
- **玩法长尾**:主角目前只有一个本地鬼剑士;位面副本、多人队伍、训练 / 每日 / 成就类任务的发放没做。
  已落地的系统各有没做完的尾巴(各章的「没做」清单见 [docs/flow.md](docs/flow.md)),要紧的几条:
  - 强化与品级折成的属性,最终怎么进伤害公式、增幅过的装备是否改取另一张强化表、品级重铸的入口、称号部位的另一套算法,都还没读清(E-395、E-404);
  - 被动技能「哪个加哪项属性」没有证据、映射留空;时装属性按约定不做(装扮只是外观);属性点服务端根本没有,不会发明;
  - 副职业只有分解做完,炼金制作与人偶只留了状态与接口;配方的技能要求、熟练度、产物升级也只留了钩子;
  - 产出里带未实现货币或宠物的一百多个箱子整箱不开,传送只留了桩;成就里条件类型读不全的只登记、不实现;宠物不进副本战斗;
  - 制作、仓库等的窗口只出数据模型,界面还没画;
  - 怪物动作的叠加动画层与声音只到事件流,画面一侧没接;叠加层的叠放细节、声音主人的客户端算法没读通,没有触发器的被动对象与出招以外的动作族不出事件流(E-406);
  - 联网房间自动机只会基础攻击(技能、跳跃、冲刺不在内);
  - 商店里的材料兑换商品(多数"零金价"商品)只到规则层,商店窗口还没接,窗口里仍按旧口径显示与购买(E-434);
  - 粒子:Squirrel 的粒子接口没有 Play 宿主消费者,被动对象型粒子与起始音效没接,画面没有对过原版(E-439);
  - 除首职业外,只通五个基类共享项和 11 条跨职业状态族配方(97/719 个主动技能能施放),换职业入口没做;怪物未决标签只做了第一簇,位移跳跃重力与牵引虚拟血量两簇另起(E-437、E-438)。
- **对拍的可复现性**:原版基线截图属于原版内容,不入库,像素对拍只有持有原版客户端的人能复现;
  合成数据测试(18,591 条)任何人都能跑。

## 原则与边界

- **仓库里没有原版内容**:`.pvf`、`.npk`、`.img`、`.ani`、`.exe`、抓包文件、反编译输出、凭据、超过 1 MiB 的文件都进不了提交。
  `tools/guard/precommit.py` 在每次提交前机械检查(安装方法见快速开始第 2 步),不靠自觉;
  凭据取值(含十六进制、Base64 等编码写法)、本机绝对路径、私钥与令牌同样进不了提交。
- **入库的金标准是合成的**:对拍用的标准向量,一部分由原版机器码在 CPU 模拟器里运行产生,另一部分来自独立的 Python 转写;
  入库的只是合成输入与对应的输出数字,不含原版代码或数据。
- **证据纪律**:每条被实现的规则都标明是「观察」「推断」还是「未知」,能追溯到证据台账里的一条记录或一次对拍;
  拿不准的写成推断,不写成事实。
- **联网只对自己的服务器**:协议逆向与实测只针对作者自己搭的私有服务器;不连官方服务,不绕过官方服务的反作弊,
  不做外挂或修改器;账号与服务器地址只放在本机未入库的配置文件里。
- **硬边界**的完整条文(包括保护层的授权范围)见 [docs/boundaries.md](docs/boundaries.md)。
