# DofUnity — DNF 的 Unity 实现

逆向《地下城与勇士》(DNF)客户端,再用 **Unity 6** 以原创代码把规则一条条重新实现出来。
运行时只读取**你自己持有的**原版数据(`Script.pvf`、`ImagePacks2/`);**本仓库不包含、不分发任何原版内容**——
素材、脚本、反编译代码一律不入库,由提交守卫机械把关(见[原则与边界](#原则与边界))。

- **目标**:Windows / macOS / Android / iOS 四个平台,用自备数据跑通「登录 → 选角 → 进城 → 进副本 → 击杀 → 结算」。
- **现状**(2026-11-13):**单机**整条流程已能在 macOS 上从选角玩到结算,成长与装备周边的系统(疲劳、觉醒、强化、制作、称号、仓库等)也陆续落地;
  **联网**(只对作者自己的服务器)已能登录、选角、进城、保持连接,在真服上走完「进副本」五步、拿到起始地图,城镇快照里的等级与职业也已从加密信封的内层读出;
  **进副本之后的战斗联网**(房间摆怪、击杀上报、结算回城,另有默认关的联网房间自动机)代码已落地,**击杀与结算的真服回包还没验证**([详见](#联网p7做到哪下一步做什么))。
- **命名**:代码里是 `DnfUnity`、`Dnf.*`、`com.dnfunity.*`;文档与注释用中文。
- **许可**:尚未选择,见[版权与许可](#版权与许可)。

## 联网(P7)做到哪、下一步做什么

**已经通的**(都在作者自己搭的服务器上实测,证据 E-357 至 E-387、E-402):
网关握手(AES-256-GCM)→ 帧层 → 14 个会话密码槽(与服务端原函数逐位一致)→ 真实登录 → 逐槽选角 → 进城包流 →
心跳保活 → 「开始游戏 → 装载通知 → 选副本 → 副本信息 → 起始地图」。Unity 开发版宿主带 `-dnfnet` 启动时,会先在后台把「网关登录 → 取游戏服地址 →
连频道 → 游戏登录 → 逐槽选角」整条链跑完再进入城镇;再带 `-dnfnetdungeon <副本编号> <模式 0–4>`,进城后会在同一条会话上接着走完进副本五步,然后接上心跳;进图后宿主还会在房间里摆出本地怪、接上联网战斗(见下);再带 `-dnfbot` 与 `-dnfnetbot`(默认关)时,联网房间里改由自动机打怪。
凭据只从本机未入库的配置文件读取(探针与宿主的用法见 [docs/usage.md](docs/usage.md))。

**曾经的卡点「561 号信封」已经解开(E-386)。** 服务端对标记为需要保护的包,统一改发编号 561 的加密信封:
角色列表与选角回包、进副本时的「开始 / 副本信息 / 起始地图」三个通知,以及(很可能)角色本体数据,都在信封里。
信封原本由客户端的反作弊/保护模块解开,那部分代码磁盘上是空的、运行期才展开,静态读码到此为止(E-374)。
后来的做法是**在 CPU 模拟器里运行原函数**(不运行游戏本体、不连官方服务,在[边界文档](docs/boundaries.md)第 3 条的授权范围内),
拿仿真结果当裁判,再把 19 个密码块核、密钥派生与完整性校验逐个用 C# 写出来:全部与裁判向量逐字节一致;
作者本机保存的 33 个真实信封,用 C# 实现解开的明文与原函数仿真的明文**逐字节一致(33 比 33)**。

**真服验证(E-387)**:进城后在同一条会话上依次完成开始游戏、等装载通知、选副本、等副本信息、等起始地图五步,
三个通知都由信封解开(实测信封全开、零未拆),宿主进副本完成、心跳正常接上。

**内层帧的解压也在真服生效(E-390、E-402)**:信封拆开后的内层帧若属于压缩包号集合,会话层现在先认 zlib 头、再用与外层同口径的严格解压器解开
(头认不出的不碰,认得出却解不开的原样交出并计数)。真服复验里,城镇快照的等级、职业、成长类型从占位符变成了数字,与所选槽里的角色对得上,收到的信封全数解开、零未拆。

**进副本之后的战斗联网:代码已落地,真服未验(E-392、E-403)**。网络层有一台状态机:起始地图的怪记录按到达顺序给本地编号,对外只认每条记录里的服务端编号;
本地怪死亡时按服务端编号发死亡命令,清图通知到达后才发结算命令,通关结果与通关奖励两段通知收齐才允许回城,每一步都有门控(报过的、不在表里的、结算已发的一律拦下、不发包)。
宿主按起始地图的怪物记录在房间里摆出同数目、同顺序的本地怪,本地击杀经状态机上报,两段结算收齐后自动回城。这一套有完整的假会话测试和变异检查;
真服上亲眼见到的只有「起始地图里有几条怪记录,状态机就列出几只」,数目对得上。

**联网房间自动机(E-407,默认关)**:带 `-dnfnetbot`(要同时带 `-dnfbot`、`-dnfnet`、`-dnfnetdungeon`,缺一项只留一行忽略日志)时,联网房间里由自动机按离线同一份决策打怪
(固定心跳补步,出手间隔与离线一致),自带停手条件并写一行状态日志,不会无限挂机:托管局失败 > 结算收齐 > 主角倒下且没有复活窗口 > 整段超时(缺省 600 秒)> 长时间没有进展(缺省 60 秒)。
它是下一次真服复验的工具;短板是只会基础攻击。不带开关时联网房间与以前一字不变。

**两个只收不用的包也拆开了(E-405)**:副本许可包是逐副本的许可档位表(条目是副本号加一字节档位,没有到期字段;带剩余秒的是选角回包里的特权列表,两回事);
选角成功回包按首字节分成功与失败,成功带载入所需的信息、失败带失败码。两者只作附加信息挂在进城结果上,选哪个槽、算不算进城仍只看原来的状态字节,
许可快照只送到 Net 层的出口、副本入口还没拿它把关;目前只有合成数据测试。

**还差什么**:

- **击杀与结算的真服回包**(E-392、E-403、E-407):下一次真服复验要看三件事——击杀被确认、清图后结算到齐、回城不断线;建议挑单房间副本、带 `-dnfnodamage`,也可以带 `-dnfnetbot` 让自动机代打。
  击杀命令现在用的是联网层缺省载荷(固定头加固定尾,除编号外服务端只做反作弊计数、不校验),服务端认不认要等真服回答。
- **联网战斗的覆盖范围**:只覆盖起始地图一张图——多房间副本里起始房杀光后服务端不会给清图通知,这一局会停在战斗中,真服核对要挑单房间副本;
  联网房间里主角死亡没有复活窗口;怪记录里除服务端编号外各项的含义没读通,所以怪的站位与种类取房间地图自己的一份;
  解析器里怪记录步长与服务端写法有 1 字节出入,也仍挂着账(代码注释里写明),没有对账。
  自动机代打(`-dnfnetbot`)也受这个范围限制:多图副本它同样只托管一间,预期走到「怪都死了、结算不来」(推断,待真服)。
- **角色本体数据**(装备、技能、背包)的解析,以及在线物品同步的来源,都还没定位到(E-382);城镇里暂用本地占位。
- 心跳回帧里的两个校验值目前填 0:服务端只累加可疑计数、不踢人,真算法需要角色本体数据(E-363)。

联网的最新、最细进展见 [docs/flow.md](docs/flow.md) 的 §75–§94、§97–§99、§109–§110、§112、§114,与[证据台账](docs/evidence/ledger.md)里的 E-357 至 E-387、E-390 至 E-392、E-402、E-403、E-405、E-407。

## 还没做、还没验证的

诚实列出,免得被「完成」二字误导:

- **联网**:见上节——击杀与结算的真服回包、多房间副本的联网战斗、角色本体数据、心跳校验值。只在作者自己的服务器上验证过。
- **平台**:只有 macOS 完整跑过。Windows(Mono)与 Android(IL2CPP)播放器最近一次构建通过是在 2026-10-21 前后(见路线图 P8a),
  此后各轮改动都没有再构建,也从未运行;iOS 缺完整 Xcode,没构建;触屏层没在真机上验证。
  macOS 播放器与编辑器测试最近一次复验是在 E-405 合并之后;E-406、E-407 这一批(2026-11-13)的宿主改动,因本机 Unity 编辑器登录态过期暂未复验,
  只通过了用引擎程序集对 Dnf.Client 源码做的类型检查。
- **人手与人耳**:键盘手感、声音对不对,没有人逐项验证过;自动化对拍只覆盖画面与逻辑。
- **推断与自己的设计**:部分数值与规则是推断或占位,界面里的中文措辞与窗口版式是自己写的、没有对过原版,
  `docs/*.md` 里的「推断」「非 REA」标注和证据台账的「置信度」列逐条写明。
- **玩法长尾**:主角目前只有一个本地鬼剑士;位面副本、多人队伍、训练 / 每日 / 成就类任务的发放没做。
  已落地的系统各有没做完的尾巴(各章的「没做」清单见 [docs/flow.md](docs/flow.md)),要紧的几条:
  - 强化与品级折成的属性,最终怎么进伤害公式、增幅过的装备是否改取另一张强化表、品级重铸的入口、称号部位的另一套算法,都还没读清(E-395、E-404);
  - 被动技能「哪个加哪项属性」没有证据、映射留空;时装属性按约定不做(装扮只是外观);属性点服务端根本没有,不会发明;
  - 副职业只有分解做完,炼金制作与人偶只留了状态与接口;配方的技能要求、熟练度、产物升级也只留了钩子;
  - 产出里带未实现货币或宠物的一百多个箱子整箱不开,传送只留了桩;成就里条件类型读不全的只登记、不实现;宠物不进副本战斗;
  - 制作、仓库等的窗口只出数据模型,界面还没画;
  - 怪物动作的叠加动画层与声音只到事件流,画面一侧没接;叠加层的叠放细节、声音主人的客户端算法没读通,没有触发器的被动对象与出招以外的动作族不出事件流(E-406);
  - 联网房间自动机只会基础攻击(技能、跳跃、冲刺不在内)。
- **对拍的可复现性**:原版基线截图属于原版内容,不入库,像素对拍只有持有原版客户端的人能复现;
  合成数据测试(10,874 条)任何人都能跑。

## 架构与目录

C# 源码**只在** `packages/` 里(Unity 的 UPM 本地包);`src/Dnf.*` 的 .NET 工程用 `<Compile Include>` 链接同一批文件,
供命令行与单元测试使用,所以 Unity 与命令行跑的是同一份代码。类库目标 `netstandard2.1`(LangVersion 9),命令行与测试 `net10.0`。

  game       纯 C# 游戏规则:状态机、命中、伤害公式、怪物数值、.act / .ai 解释、Squirrel 原生接口、任务 / 技能 / 异常状态

  play       副本房间战斗、怪物、技能、HUD、整条流程、自动机(含联网房间自动机)
  net        网关客户端、帧层、会话密码、登录 / 选角 / 进城 / 心跳、通知解析、561 信封解包与内层帧解压、副本许可与选角回包解析、在线进副本编排、联网战斗状态机

## 快速开始

目前只在 **macOS** 上验证过。需要 .NET SDK 10(`global.json` 锁定);要跑播放器再装 Unity 6000.3.26f1。

```sh
# 1. 先跑合成数据测试——不需要任何原版数据(10,874 条,2026-11-13 在全新检出里实测全部通过;已构建过时约半分钟到两分钟,看机器负载)
. tools/env.sh                       # 仅当 dotnet 装在 ~/.dotnet 且不在 PATH 里时需要
dotnet test DnfUnity.slnx -c Release

# 2. 准备你自己的数据目录(含 Script.pvf 与 ImagePacks2/),并装上提交守卫(贡献者必装)
cp local.env.example local.env       # 把 DNF_DIR 改成你自己的游戏目录
sh tools/guard/install-hooks.sh

# 3. 用你的数据做全库对拍与读通(部分项还需要本机逆向产物,见脚本头注释)
tools/verify-all.sh

# 4. 构建 macOS 播放器,从选角一路玩到结算
tools/unity-build-town.sh macos
tools/play-dungeon.sh flow
```

更多命令(命令行子命令、自动机、联网探针、各平台构建、清理 agent 残留进程的看门狗)见 [docs/usage.md](docs/usage.md)。
维护者要把本地分支与标签发布到 GitHub,**不要直接 `git push`**(更不要 `--all`、`--mirror`),用 `tools/publish-github.sh`:
它先审计每个引用的整段历史、脱敏、校验,再对远端只做快进(原因、范围与用法见同一份手册末尾)。

## 原则与边界

- **仓库里没有原版内容**:`.pvf`、`.npk`、`.img`、`.ani`、`.exe`、抓包文件、反编译输出、凭据、超过 1 MiB 的文件都进不了提交。
  `tools/guard/precommit.py` 在每次提交前机械检查(安装方法见快速开始第 2 步),不靠自觉;
  凭据取值(含十六进制、Base64 等编码写法)、本机绝对路径、私钥与令牌同样进不了提交。
- **入库的金标准是合成的**:对拍用的标准向量,一部分由原版机器码在 CPU 模拟器里运行产生,另一部分来自独立的 Python 转写;
  入库的只是合成输入与对应的输出数字,不含原版代码或数据。
- **证据纪律**:每条被实现的规则都标明是「观察」「推断」还是「未知」,能追溯到证据台账里的一条记录或一次对拍;
  拿不准的写成推断,不写成事实。
- **联网只对自己的服务器**:协议逆向与实测只针对作者自己搭的私有服务器;不连官方服务,不绕过官方服务的反作弊,
  不做外挂或修改器;账号与服务器地址只放在本机未入库的配置文件里。
- **硬边界**的完整条文(包括保护层的授权范围)见 [docs/boundaries.md](docs/boundaries.md)。
