# DofUnity — DNF 的 Unity 实现

逆向《地下城与勇士》(DNF)客户端,再用 **Unity 6** 以原创代码把规则一条条重新实现出来。
运行时只读取**你自己持有的**原版数据(`Script.pvf`、`ImagePacks2/`);**本仓库不包含、不分发任何原版内容**——
素材、脚本、反编译代码一律不入库,由提交守卫机械把关(见[原则与边界](#原则与边界))。

- **目标**:Windows / macOS / Android / iOS 四个平台,用自备数据跑通「登录 → 选角 → 进城 → 进副本 → 击杀 → 结算」。
- **现状**(2026-11-09):**单机**整条流程已能在 macOS 上从选角玩到结算;**联网**已能登录、选角、进城并保持连接,
  **卡在「进副本」**——关键数据被服务端封进加密信封,暂时解不开([详见](#联网p7卡在哪下一步做什么))。
- **命名**:代码里是 `DnfUnity`、`Dnf.*`、`com.dnfunity.*`;文档与注释用中文。
- **许可**:尚未选择,见[版权与许可](#版权与许可)。

| 保持连接 | — | ✅ 心跳保活,实测长驻 640 秒不断线 |

**一句话**:离线版已经是一个能玩的原型——可走动的城镇,346 个副本全部接入,自动机整库扫描能通关其中 303 个;

## 联网(P7)卡在哪、下一步做什么

**已经通的**(都在作者自己搭的服务器上实测,证据 E-357 至 E-376):
网关握手(AES-256-GCM)→ 帧层 → 14 个会话密码槽(与服务端原函数逐位一致)→ 真实登录 → 逐槽选角 → 进城包流 →
心跳保活 → 「开始游戏 → 选副本」。Unity 开发版宿主带 `-dnfnet` 启动时,会先在后台把「网关登录 → 取游戏服地址 →
连频道 → 游戏登录 → 逐槽选角」整条链跑完再进入城镇;凭据只从本机未入库的配置文件读取。

**卡点:「561 号信封」。** 服务端对标记为需要保护的包,统一改发编号 561 的加密信封:角色列表与选角回包、
角色本体数据(装备、技能、背包,很可能)、进副本时的「开始 / 副本信息 / 起始地图」三个通知,都在信封里。
信封由客户端的反作弊/保护模块解开。静态读码已把解包路径定位到函数级,但变换本体在保护库里——
磁盘上的代码节为空、运行期才展开,主程序里的接收点也只是虚拟机桩——**静态分析到此为止**(E-374)。

**它为什么挡住了击杀**:怪物死亡包要报的怪物编号来自组图时的随机基数,本地推算不出,只能随起始地图下发
(E-376,推断);起始地图恰好在信封里。所以信封是击杀环节的**唯一前置**([flow.md](docs/flow.md) §88)。

**要解开它,需要二选一**(目前都没有,需要项目持有者决定):

1. 与服务器版本匹配的客户端映像;
2. 对保护壳做离线仿真的单独授权。

**在此之前能做的**([flow.md](docs/flow.md) §87、§88):

- 不依赖信封的在线副本:按本地数据生成起始房与怪物(与单机副本同一套构建),再发真实的位置包、技能包,探服务端的校验口径。
  这条路**打不了怪**(见上),只能把能探的校验先探清。
- 已提前落库的明文解析器:进城完成与时间同步(E-371)、副本信息与起始地图(E-375)——信封一解开,内层帧可以直接喂进去。
  怪记录步长与服务端写法有 1 字节出入,已在代码注释里挂账,拿到真实帧时第一件事是对账。
- 心跳回帧里的两个校验值目前填 0:服务端只累加可疑计数、不踢人,真算法需要角色本体数据(E-363)。

最新、最细的进展以 [docs/flow.md](docs/flow.md) 末尾几节(§75–§88)和[证据台账](docs/evidence/ledger.md)末尾(E-357 至 E-376)为准。

## 还没做、还没验证的

诚实列出,免得被「完成」二字误导:

- **联网**:见上节——进副本之后的一切(击杀、结算)、角色本体数据、心跳校验值。只在作者自己的服务器上验证过。
- **平台**:只有 macOS 完整跑过。Windows(Mono)与 Android(IL2CPP)播放器最近一次构建通过是在 2026-10-21 前后(见路线图 P8a),
  此后各轮改动都没有再构建,也从未运行;iOS 缺完整 Xcode,没构建;触屏层没在真机上验证。
- **人手与人耳**:键盘手感、声音对不对,没有人逐项验证过;自动化对拍只覆盖画面与逻辑。
- **推断与自己的设计**:部分数值与规则是推断或占位,界面里的中文措辞与窗口版式是自己写的、没有对过原版,
  `docs/*.md` 里的「推断」「非 REA」标注和证据台账的「置信度」列逐条写明。
- **玩法长尾**:主角目前只有一个本地鬼剑士;装备品级与强化、套装与称号效果、疲劳、位面副本、多人队伍、
  训练 / 每日 / 成就类任务的发放等没做(各章的「没做」清单见 [docs/flow.md](docs/flow.md))。
- **对拍的可复现性**:原版基线截图属于原版内容,不入库,像素对拍只有持有原版客户端的人能复现;
  合成数据测试(6,044 条)任何人都能跑。

## 架构与目录

C# 源码**只在** `packages/` 里(Unity 的 UPM 本地包);`src/Dnf.*` 的 .NET 工程用 `<Compile Include>` 链接同一批文件,
供命令行与单元测试使用,所以 Unity 与命令行跑的是同一份代码。类库目标 `netstandard2.1`(LangVersion 9),命令行与测试 `net10.0`。

```
packages/com.dnfunity.*   唯一的源码所在
  data       PVF / NPK / IMG v2 读取、解码、标签解析
  squirrel   Squirrel 3.2 虚拟机的 C# 封装 + 预编译原生插件(macOS、Android)
  script     脚本宿主:按原版加载约定从 PVF 运行 .nut
  game       纯 C# 游戏规则:状态机、命中、伤害公式、怪物数值、.act / .ai 解释、Squirrel 原生接口、任务 / 技能 / 异常状态
  render     纯 C# CPU 合成器与城镇场景(Unity GPU 路径的参照实现)
  play       副本房间战斗、怪物、技能、HUD、整条流程、自动机
  net        网关客户端、帧层、会话密码、登录 / 选角 / 进城 / 心跳、通知解析
  client     Unity 层:800×600 像素对齐的舞台、GPU 绘制、输入、音频、字体、触屏
src/Dnf.*                 同一批源码的 .NET 工程 + 各包的测试;Dnf.Cli 是命令行(`dnf`),Dnf.NetProbe 是联网探针
unity/DnfUnity/           Unity 6000.3.26f1 工程(Editor 测试、冒烟、演示场景),经 file: 引用上面 8 个包
native/                   Squirrel 3.2 原版源码(MIT,未改动)与宿主封装 dnfsq
tools/                    构建 / 播放 / 验证脚本、Python 参考实现与 CPU 模拟器对拍、Ghidra 脚本、基线录制、提交守卫
docs/                     文档(索引见 docs/README.md)
re/  out/                 逆向产物与生成物:只在本机,已被 .gitignore 排除
```

规模:约 23.6 万行 C#(其中测试约 10.7 万行)、约 1.8 万行 Python;文档 30 份左右,证据台账 376 条。

## 快速开始

目前只在 **macOS** 上验证过。需要 .NET SDK 10(`global.json` 锁定);要跑播放器再装 Unity 6000.3.26f1。

```sh
# 1. 先跑合成数据测试——不需要任何原版数据(6,044 条,2026-11-09 实测全部通过)
dotnet test DnfUnity.slnx -c Release

# 2. 准备你自己的数据目录(含 Script.pvf 与 ImagePacks2/),并装上提交守卫(贡献者必装)
cp local.env.example local.env       # 把 DNF_DIR 改成你自己的游戏目录
sh tools/guard/install-hooks.sh

# 3. 用你的数据做全库对拍与读通(部分项还需要本机逆向产物,见脚本头注释)
tools/verify-all.sh

# 4. 构建 macOS 播放器,从选角一路玩到结算
tools/unity-build-town.sh macos
tools/play-dungeon.sh flow
```

更多命令(命令行子命令、自动机、联网探针、各平台构建)见 [docs/usage.md](docs/usage.md)。

## 原则与边界

- **仓库里没有原版内容**:`.pvf`、`.npk`、`.img`、`.ani`、`.exe`、抓包文件、反编译输出、凭据、超过 1 MiB 的文件都进不了提交。
  `tools/guard/precommit.py` 在每次提交前机械检查(安装方法见快速开始第 2 步),不靠自觉。
- **入库的金标准是合成的**:对拍用的标准向量,一部分由原版机器码在 CPU 模拟器里运行产生,另一部分来自独立的 Python 转写;
  入库的只是合成输入与对应的输出数字,不含原版代码或数据。
- **证据纪律**:每条被实现的规则都标明是「观察」「推断」还是「未知」,能追溯到证据台账里的一条记录或一次对拍;
  拿不准的写成推断,不写成事实。
- **联网只对自己的服务器**:协议逆向与实测只针对作者自己搭的私有服务器;不连官方服务,不绕过官方服务的反作弊,
  不做外挂或修改器;账号与服务器地址只放在本机未入库的配置文件里。
- **硬边界**的完整条文(包括保护层的授权范围)见 [docs/boundaries.md](docs/boundaries.md)。
